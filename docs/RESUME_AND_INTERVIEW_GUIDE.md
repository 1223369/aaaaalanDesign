# Gzm Design 简历文案与面试题库

本文档分为两部分：

## 一、简历项目文案

### 项目名称

Gzm Design 在线海报设计器

### 项目定位

Gzm Design 是一套基于 Vue 3、TypeScript、Vite 和 Leafer UI 实现的在线海报设计器，支持多页面画布编辑、图层管理、模板导入、PSD 文件解析、富文本编辑、二维码/条形码生成、素材管理、画布缩放拖拽、JSON/图片导出等能力，面向营销物料、海报制作、运营设计等场景。

### 技术栈

Vue 3、TypeScript、Vite、Pinia、Vue Router、Arco Design Vue、UnoCSS、Leafer UI、ag-psd、Axios、MockJS、TinyMCE、fontfaceobserver。

### 简历描述版本 A：偏业务价值

参与开发在线海报设计器 Gzm Design，项目面向运营海报、营销素材和模板化设计场景，提供浏览器端可视化编辑能力。负责编辑器核心模块和交互能力建设，包括基于 Leafer UI 封装画布服务、实现元素添加/选中/缩放/层级管理、多页面工作区切换、模板 JSON 导入导出、PSD 图层解析和字体加载等功能。通过 Vue 3 组件化拆分左侧素材栏、中心画布、右侧属性面板和顶部工具栏，结合 Pinia、事件总线和依赖注入机制降低模块耦合，提升编辑器可维护性和扩展性。

### 简历描述版本 B：偏技术架构

负责 Gzm Design 在线海报设计器前端架构设计与核心能力实现。项目采用 Vue 3 + TypeScript + Vite 构建 UI 层，基于 Leafer UI 封装 `MLeaferCanvas` 画布服务，统一管理画布实例、内容层、编辑画板、选中对象、缩放状态和多页面 JSON 数据。引入类 VS Code 风格的依赖注入体系管理 EventBus、Workspaces、Hierarchy、Keybinding、UndoRedo 等服务，通过事件总线解耦工作区切换、画布数据保存和页面恢复逻辑。实现 PSD 导入解析，将 Photoshop 图层转换为 Leafer 的 Text、HTMLText、Image、Group 等可编辑对象，并通过字体提取和懒加载保证模板渲染一致性。

### 简历描述版本 C：偏个人贡献

在 Gzm Design 项目中主要负责编辑器核心逻辑和复杂交互功能开发：

1. 封装 Leafer 画布服务，统一提供元素添加、选中、缩放、JSON 导入导出、多页面切换等 API。
2. 设计工作区服务和事件总线机制，实现页面切换前保存当前画布、切换后恢复目标页面数据。
3. 开发左侧素材面板、画布挂载组件和右侧属性面板联动逻辑，实现 UI 操作驱动画布对象变化。
4. 接入 PSD 解析能力，完成普通文本、富文本、图片、分组、蒙版等图层向编辑器对象的转换。
5. 优化字体加载流程，支持从模板 JSON 中提取字体并按需加载，减少文本渲染偏差。
6. 通过插件化和依赖注入方式组织编辑器模块，提高复杂编辑器功能的可扩展性。

### 简历描述版本 D：一句话浓缩

基于 Vue 3 + TypeScript + Leafer UI 开发浏览器端在线海报设计器，负责画布服务封装、多页面工作区、图层管理、PSD 导入、模板 JSON 导入导出、字体加载和插件化架构设计。

### 简历项目亮点

1. 不是普通后台页面，而是复杂交互型可视化编辑器。
2. 画布编辑能力封装为服务，Vue 组件只负责触发操作和展示状态。
3. 使用依赖注入管理多个编辑器服务，降低模块耦合。
4. 使用事件总线解耦工作区、多页面和画布保存恢复逻辑。
5. 支持 PSD 导入，把外部设计文件转换为可编辑画布对象。
6. 支持多页面 JSON 数据结构，便于模板保存、导入、导出。
7. 支持富文本、字体加载、二维码、条形码、图片导出等复杂业务能力。

### 面试自我介绍项目版

我最近做的一个比较有代表性的项目是 Gzm Design 在线海报设计器。它不是传统表单型前端项目，而是一个浏览器端可视化编辑器。项目使用 Vue 3、TypeScript 和 Vite 构建 UI，画布核心基于 Leafer UI。我主要关注编辑器核心架构，包括画布服务封装、多页面工作区、图层管理、PSD 导入、模板 JSON 导入导出以及字体加载。整体设计上，我把 Vue 组件和画布逻辑做了分层：Vue 负责左侧素材栏、右侧属性面板、顶部工具栏等 UI，真正的画布操作统一收敛到 `MLeaferCanvas` 服务里；服务之间通过依赖注入和事件总线协作，避免组件直接互相调用。这个项目让我对复杂前端状态、画布编辑器、模块解耦和性能优化都有比较深入的实践。

### 面试回答项目难点版

这个项目最大的难点是编辑器状态复杂。普通页面的状态通常是表单字段和列表数据，但海报设计器里有画布实例、选中对象、图层树、多页面 JSON、缩放比例、工具状态、字体加载状态和导入导出流程。如果这些状态全部散落在 Vue 组件里，会非常难维护。所以我把画布操作封装成 `MLeaferCanvas` 服务，并把工作区、事件总线、层级、快捷键、撤销恢复等能力拆成独立服务。组件通过 `useEditor()` 拿服务，服务之间通过事件协作。比如切换页面时，工作区服务只负责发 `workspaceChangeBefore` 和 `workspaceChangeAfter`，画布服务监听事件后保存旧页面 JSON 并恢复新页面 JSON。这样职责边界更清楚，后续扩展也更稳定。

### 面试回答技术亮点版

技术亮点主要有三个。第一是画布服务封装，我没有让各个 Vue 组件直接操作 Leafer 实例，而是通过统一的 `editor.add`、`importJsonToCurrentPage`、`zoomToFit` 等 API 操作画布。第二是多页面和事件总线设计，页面切换前后通过事件完成数据保存和恢复，减少模块直接依赖。第三是 PSD 导入，项目使用 `ag-psd` 解析 Photoshop 文件，再把 PSD 图层转换成 Leafer 的 Text、HTMLText、Image、Group 等对象，同时处理字体、颜色、描边、段落样式等属性转换。

## 二、200+ 延展面试题库

下面每道题都按“主问题 + 延展追问”设计。面试中常见情况是面试官先问一个 A，如果你回答得比较好，会继续追问 A1、A2、A3。建议准备时不要只背答案，而是按链路理解。

### A. 项目整体与业务理解

1. 主问题：这个项目是做什么的？延展追问：它和普通后台管理系统最大的区别是什么？
   - **答**：Gzm Design 是一款基于 Vue 3 + TypeScript 和 Leafer UI 实现的在线海报设计器。它与普通后台管理系统的最大区别在于，后者以数据表格和表单的 CRUD 业务为主，界面简单；而海报设计器是高频交互的可视化图形编辑器，需要处理画布对象模型、图层排序、撤销恢复、实时缩放和高精度的第三方文件（如 PSD）解析渲染，在状态管理和复杂图形计算上有极高要求。
2. 主问题：为什么这个项目可以写进简历作为重点项目？延展追问：它体现了哪些复杂前端能力？
   - **答**：因为该项目不仅涵盖了前端工程化的全部要素（Vite+TS+Pinia），还深度应用了依赖注入设计模式、事件总线解耦方案以及 HTML5 Canvas 图形学应用。它体现了画布封装、高性能响应式控制、多页面生命周期数据同步、PSD 二进制解析与跨域图片处理等中高级前端必须掌握的架构设计与性能优化能力。
3. 主问题：Gzm Design 的核心用户场景是什么？延展追问：如果面向运营人员，你会关注哪些易用性问题？
   - **答**：核心场景是运营海报制作、活动裂变图生成、社交物料设计。面向运营人员时，我们会重点关注易用性问题：如对齐辅助线与智能吸附、一键套用模板、文字双击就地编辑、画布缩放自适应、快捷键的可用性，以及误操作后的一键撤销（Undo/Redo）。
4. 主问题：在线海报设计器的核心能力有哪些？延展追问：哪些能力是 MVP 阶段必须有的？
   - **答**：核心能力包括：画布基本操作（添加、选中、变换、删除元素）、文本编辑（普通/富文本）、图片素材库与上传、多页面管理、模板 JSON 导入导出。在 MVP 阶段，支持基础形状、文本、图片图层，以及能将设计导出为图片和导入保存好的 JSON 模板是必须拥有的能力。
5. 主问题：这个项目的核心技术难点是什么？延展追问：你如何证明自己解决了这些难点？
   - **答**：核心难点在于画布状态的解耦和响应式性能优化。海报设计器中有大量的画布复杂对象，直接放进 Vue 响应式系统会被深度劫持导致极大的性能开销。我通过使用 shallowRef 代理选中对象，将复杂的画布渲染逻辑封装在纯 TS 类中，用依赖注入和事件总线与 Vue 视图解耦，实现了 UI 层和渲染层的彻底分离。
6. 主问题：这个项目有哪些页面？延展追问：为什么编辑器页面是核心页面？
   - **答**：项目主要包含模板中心、海报编辑页和 PSD 解析页等。编辑器页面是核心，因为它是用户所有的编辑、排版操作的载体，也是所有画布服务、状态管理、依赖注入以及各种插件（文字、形状、条码等）工作的中心上下文。
7. 主问题：项目的数据最终以什么形式保存？延展追问：为什么 JSON 对设计器很重要？
   - **答**：最终以多页面 JSON 格式的字符串或对象进行保存。JSON 对设计器而言极其重要，因为它将原本复杂的画布 DOM 和图形实例状态扁平化、结构化，不仅体积小利于网络传输和数据库存储，还利于在前端通过统一的数据 Schema 校验实现跨平台和多端的模板数据恢复与重绘。
8. 主问题：项目支持 PSD 导入有什么业务意义？延展追问：PSD 导入和模板 JSON 导入有什么区别？
   - **答**：业务意义在于极大降低了设计师和运营的协作成本，设计师可以直接将 PSD 拖入浏览器生成可编辑模板，无需手动拼凑。PSD 导入是将外部 PSD 二进制解析为具体的图层属性再重构为编辑器实例；而模板 JSON 导入是直接读取由本系统自身导出的标准化 Schema，两者解析复杂度和数据源完全不同。
9. 主问题：为什么在线设计器比普通表单系统状态更复杂？延展追问：复杂状态会带来哪些维护问题？
   - **答**：因为设计器中不仅有表单属性，还包含大量画布内部实例、视口缩放、操作历史栈、字体文件动态加载、快捷键绑定状态等。这会带来状态同步冲突（Vue 状态与 Canvas 状态不一致）、深层响应式代理导致极其卡顿、撤销恢复链路难以设计等维护难题。
10. 主问题：你在这个项目中主要负责什么？延展追问：哪些模块最能体现你的个人贡献？
   - **答**：主要负责编辑器核心架构的搭建，包括基于 Leafer UI 封装 MLeaferCanvas 画布服务，引入依赖注入模式管理工作区与事件总线，实现多页面模板数据的保存与恢复机制，并参与了 PSD 导入中富文本、图片、分组等图层向 Leafer 对象映射的 parser 模块研发。

### B. 技术栈选择

11. 主问题：为什么使用 Vue 3？延展追问：Composition API 对这个项目有什么帮助？
   - **答**：Vue 3 提供了 Composition API，使得逻辑复用和代码组织更加清晰，特别适合把复杂的属性面板联动拆分为独立的 hooks。此外，Vue 3 的响应式系统底层使用 Proxy，在处理海量图层响应和 shallowRef 性能控制上相比 Vue 2 的 Object.defineProperty 拥有决定性的性能优势。
12. 主问题：为什么使用 TypeScript？延展追问：复杂画布对象场景下类型系统有什么价值？
   - **答**：TypeScript 提供了严谨的类型约束和 IDE 自动补全。在复杂画布场景下，各种元素（图片、文字、条码等）都拥有各自特有的配置字段，通过定义严格的 Type/Interface 和泛型，可以避免在开发阶段拼写错属性键值，极大减少了由于属性不一致导致的画布渲染崩溃 Bug。
13. 主问题：为什么使用 Vite？延展追问：Vite 相比 Webpack 在开发体验上有什么优势？
   - **答**：Vite 采用基于 ESM 的冷启动方案，热更新速度极快，在开发拥有数百个组件的复杂编辑器系统时，体验远远好于 Webpack。它的按需编译和开箱即用的 CSS、TS 配置也大幅节省了项目初始搭建的工程化成本。
14. 主问题：为什么使用 Pinia？延展追问：为什么没有把所有画布状态都放进 Pinia？
   - **答**：Pinia 用于管理全局轻量级的业务状态，例如当前选中的活动工具（activeTool）、动态字体列表、界面 loading 状态等。没有把所有画布对象放进 Pinia，是因为 Leafer App 实例是拥有海量内部引用和方法的重量级对象，放进 Pinia 会导致深度代理，产生巨大的性能损耗。
15. 主问题：为什么使用 Vue Router？延展追问：为什么项目使用 hash 路由？
   - **答**：Vue Router 提供了多页面（首页、编辑器、解析页）的无缝跳转。项目使用 hash 路由（createWebHashHistory），原因在于它无需后端或 Nginx 针对单页面应用做特殊的 try_files 伪静态配置，在部署静态托管（例如 CDN、GitHub Pages）或者被作为微前端子应用嵌入时更不易出错。
16. 主问题：为什么使用 Arco Design Vue？延展追问：组件库在复杂业务项目里有哪些优缺点？
   - **答**：Arco Design Vue 作为火山引擎开源的组件库，提供了诸如弹窗（Modal）、颜色选择器、滑块（Slider）、表单（Form）等丰富的 UI 控件，极大加速了属性控制面板的搭建。缺点是复杂定制时可能需要改样式变量，优点是开箱即用，质量高且生态完整。
17. 主问题：为什么使用 UnoCSS？延展追问：原子化 CSS 对页面开发效率有什么影响？
   - **答**：UnoCSS 是原子化 CSS 引擎，它免去了手写各种小组件样式和 `<style scoped>` 的痛苦，通过在类名写 `p-times-10`、`flex` 等直接编译出样式，极大提升了布局开发效率，同时能够让项目体积最小化，符合项目快速响应的要求。
18. 主问题：为什么使用 Leafer UI？延展追问：它和 Canvas 原生 API、Fabric.js 有什么区别？
   - **答**：Leafer UI 是一款极速的 Canvas 2D 绘图引擎，其渲染速度比传统 Fabric.js 快数倍，且内部具有开箱即用的 Frame/Box/App 架构，非常适合海报设计器这样包含多个层级嵌套的场景；与原生 API 相比，它提供了更高维的图形对象化操作和事件机制。
19. 主问题：为什么使用 ag-psd？延展追问：PSD 解析库只能解决哪部分问题？
   - **答**：删除页面时，首先在列表数组中移出对应 ID。如果是删除当前活动页，系统会自动计算并切换到列表中的上一页或下一页（如果没有其他页面，则会重新初始化一页空白页）；同时，在画布 Map 中删除对应的 key，最后触发 `workspaceChangeAfter` 加载新活动页数据。
20. 主问题：为什么使用 TinyMCE？延展追问：富文本编辑和普通文本编辑有什么不同？
   - **答**：TinyMCE 是一款强大的富文本编辑器。在项目中，普通文本编辑通常是一行字或基础样式，而海报文字常常需要部分字标红、加粗、改字号等富文本编辑。使用 TinyMCE 可以让用户在弹窗中以所见即所得的形式编辑富文本，再将生成的 HTML 同步至编辑器的 HTMLText 组件中渲染。
21. 主问题：为什么使用 fontfaceobserver？延展追问：字体加载失败会对画布产生什么影响？
   - **答**：fontfaceobserver 是用于监听网络字体加载状态的轻量工具库。如果字体加载失败，画布会使用浏览器默认的衬线或非衬线字体，这会导致文字排版发生移位、宽度计算偏差甚至排版溢出，从而破坏导出的海报视觉效果。
22. 主问题：为什么使用 Axios？延展追问：请求拦截器统一处理哪些问题？
   - **答**：Axios 是基于 Promise 的网络请求库，方便统一处理 API 交互。我们的请求拦截器统一处理了添加 Token 认证、规范化 API 请求前缀，而响应拦截器则拦截处理全局报错提示（如未登录 401 重定向）及统一格式的 response.data 剥离。
23. 主问题：为什么使用 MockJS？延展追问：前后端并行开发中 mock 有什么价值？
   - **答**：MockJS 用于在后端 API 尚未开发完毕时进行数据模拟。它能让前端在不依赖真实网络请求的情况下，独立跑通海报模板列表、素材列表等功能的业务流，实现前后端无缝并行开发，并保证接口数据 Schema 的提前对齐。
24. 主问题：为什么使用 lodash？延展追问：在层级管理里它解决了什么问题？
   - **答**：lodash 在项目里主要解决了深拷贝（cloneDeep）、防抖（debounce，用于缩放或拖拽的频繁触发优化）、以及在层级管理中快速获取图层数组的最后一个元素（_.last）等，在处理树状的图层操作时提供了极其健壮的工具方法支持。
25. 主问题：为什么使用 uuid？延展追问：如果 id 冲突会影响哪些功能？
   - **答**：uuid 在画布元素初始化或新页面创建时，为它们生成独一无二的业务级 ID。如果 ID 冲突，会导致属性面板联动错乱、图层删除/隐藏失败、或者切换页面保存和撤销历史记录中出现错位覆盖。

### C. 工程入口与构建配置

26. 主问题：项目从哪个文件启动？延展追问：`index.html`、`main.ts`、`App.vue` 分别负责什么？
   - **答**：项目启动时，首先加载 index.html，浏览器接着载入 /src/main.ts（核心入口），最后将根组件 App.vue 挂载到 DOM 树上。index.html 充当承载容器，main.ts 初始化全局服务与插件，App.vue 提供基础骨架和路由出口。
27. 主问题：`main.ts` 做了哪些事情？延展追问：插件注册顺序会不会影响项目？
   - **答**：main.ts 主要执行了：导入 CSS 样式（样式重置、UnoCSS 等）、初始化 Pinia、初始化 Vue Router、注册 Mock 服务、配置 Axios 拦截器，以及将全局的 Vue 指令或组件挂载到 app 实例上。插件注册顺序很关键，如 Pinia 必须在路由和挂载依赖它的组件之前注册。
28. 主问题：`app.use(core)` 的意义是什么？延展追问：Vue 插件的 install 方法何时执行？
   - **答**：app.use(core) 是通过 Vue 的插件机制来初始化项目的核心架构（例如依赖注入的全局服务容器）。Vue 插件的 install 方法在 main.ts 执行到 app.use 时立即同步执行，接收当前的 app 实例作为参数，并将其挂载到 app.config.globalProperties 上。
29. 主问题：为什么 `main.ts` 中要导入 `request.ts`？延展追问：这种副作用导入有什么风险？
   - **答**：是为了利用文件的副作用（Side Effect）在 main.ts 启动时立即执行文件中的全局 Axios 拦截器注册和默认实例配置。风险在于副作用导入如果带有未处理的报错，会直接阻塞整个 Vue 应用的初始化，且依赖关系隐式，不够清晰。
30. 主问题：为什么要导入 mock 模块？延展追问：生产环境是否应该启用 mock？
   - **答**：导入 mock 模块是为了拦截 Axios 请求并返回模拟数据。在生产环境中，应该通过 Vite 环境变量（如 VITE_MOCK === 'true'）结合动态导入或打包配置（如 conditional compilation）彻底排除 mock 代码，以防生产 API 被误拦截并减小打包体积。
31. 主问题：Vite 中 `@` 别名有什么作用？延展追问：路径别名对大型项目维护有什么好处？
   - **答**：path alias `@` 映射到项目中的 `/src` 目录。在大型项目中，这不仅缩短了导入语句的长度，还能避免使用繁琐的相对路径（如 `../../../../utils`），即便文件在目录间移动也不必改动导入路径，极大便利了维护。
32. 主问题：AutoImport 的作用是什么？延展追问：自动导入会带来哪些可读性问题？
   - **答**：AutoImport 插件让我们在编写 Vue 组件时，无需显式写 `import { ref, computed } from 'vue'`，由 Vite 构建时自动检测并注入。这虽然提升了开发效率，但如果滥用可能会让新手感到困惑，降低代码中 API 来源的显式可读性。
33. 主问题：Components 自动注册解决什么问题？延展追问：为什么仍然有些组件需要手动 import？
   - **答**：Components 自动注册插件免去了每次使用 Arco Design 或公共组件时在 `<script>` 中手动 import 和 components 注册。但对于一些动态挂载的、非模板标签渲染的 API 组件（如 `Message` 或特定服务中实例化的弹窗），依然需要手动引入。
34. 主问题：SVG 图标插件的作用是什么？延展追问：symbolId 如何影响图标使用？
   - **答**：SVG 图标插件将项目中的 SVG 静态图标自动打包成 SVG Sprites 并生成 `symbolId`。这样在页面上仅需要通过一个统一的 SVG 标签组件（如 `<svg-icon name="xxx">`）结合 symbolId 即可直接渲染，省去了多次发网络请求或手动内联的麻烦。
35. 主问题：UnoCSS 的虚拟 CSS 是什么？延展追问：为什么要导入 `virtual:uno.css`？
   - **答**：UnoCSS 的虚拟 CSS 是指通过解析源文件中的 CSS 类名，在内存中动态按需生成最终的 CSS 样式文件。`import 'virtual:uno.css'` 就是把这个动态生成的虚拟样式文件引入到项目中，从而在浏览器端生效，不会产生无用样式，体积极小。
36. 主问题：为什么需要 CSS reset？延展追问：不同浏览器默认样式会造成什么问题？
   - **答**：由于各个浏览器内置的 user-agent stylesheet 默认样式不统一（如 margin, padding, list-style 差异），会导致同一套排版在 Chrome、Firefox 下有像素级的视觉偏差。重置 CSS（如 normalize.css）能抹平这些偏差，提供一致的排版基准。
37. 主问题：`type: module` 有什么影响？延展追问：ESM 和 CommonJS 有什么区别？
   - **答**：`type: module` 告诉 Node.js 该目录下的 JS/TS 文件均采用 ES Modules 语法规范。ESM 支持静态编译（import/export），便于构建工具进行 tree-shaking 优化；而 CommonJS 采用运行时加载（require），在浏览器端无法原生直接使用。
38. 主问题：`dev`、`build`、`preview` 分别做什么？延展追问：为什么 build 后还需要 preview？
   - **答**：dev 启动本地热更新开发服务器；build 执行打包，将 TS 和 Vue 组件编译、压缩为生产静态文件；preview 可以在本地启动静态服务托管打包好的 dist 目录。preview 对于在上线前真实复现、排查生产打包后的 Bug 具有重要作用。
39. 主问题：`vite.config.ts` 为什么导出 `defineConfig(config)`？延展追问：函数式配置适合哪些场景？
   - **答**：它使用 defineConfig 是为了在 TS 下获得完美的配置文件类型提示和校验。函数式配置（(env) => config）能够让配置文件根据当前运行环境（如开发、生产）动态返回不同的端口、代理和插件配置，适应多环境部署。
40. 主问题：如何配置不同环境的 API 地址？延展追问：环境变量暴露到前端有什么安全风险？
   - **答**：通过在项目根目录配置 `.env.development` 和 `.env.production`，使用 `VITE_APP_BASE_URL` 等前缀变量由 Vite 载入并暴露。暴露敏感环境变量风险极高（如 API Key），因为被 `VITE_` 前缀修饰的变量在打包后会被硬编码到前端客户端代码中，任何人都能查看到。

### D. 路由与页面组织

41. 主问题：项目有哪些主要路由？延展追问：为什么 `/editor` 是核心路由？
   - **答**：主要包含首页工作台 `/home`、海报编辑器 `/editor`、以及 PSD 解析展示页 `/psd`。其中 `/editor` 是核心，因为它需要承载大体积的 Canvas 初始化代码、编辑器服务容器和繁多的小属性设置面板。
42. 主问题：为什么使用 `createWebHashHistory`？延展追问：hash 路由和 history 路由部署区别是什么？
   - **答**：因为 Hash 模式（URL 中带 #）是纯前端路由，在刷新页面时，浏览器仍请求的是 index.html，不会向服务器发送真实的子路径请求，因此不需要配置服务器伪静态。而 History 模式刷新时如果 Nginx 没有配置重定向，会直接报 404 错误。
43. 主问题：`router-view` 在 App.vue 中如何工作？延展追问：动态组件渲染有什么好处？
   - **答**：在 App.vue 中，通过 `router-view` 监听当前激活的路由组件，并结合 `<component :is="Component">` 动态渲染。结合动态组件可以方便地加入 Vue 内置的 `<keep-alive>` 缓存和动画过渡 `<transition>`，丰富页面切换体验。
44. 主问题：首页和编辑器页职责有什么区别？延展追问：如果首页直接进编辑器有什么利弊？
   - **答**：首页主要用于管理用户自己保存的海报列表、海报模板展示、新建尺寸等；编辑器页负责海报的精细化修改与渲染。不建议直接进编辑器，因为需要先给用户提供选择模板、指定海报尺寸的入口，保证海报元数据的初始完整。
45. 主问题：PSD 解析页和编辑器页如何关联？延展追问：PSD 导入应该放独立页还是编辑器内部？
   - **答**：用户可以通过解析页上传 PSD 文件并查看转换进度，解析完成后，会通过路由参数（如 templateId）或临时状态跳转到编辑器页恢复该 PSD 的图层。放在编辑器内部体验更好，可以让用户在编辑过程中随时导入 PSD 作为图层参考。
46. 主问题：如何做路由懒加载？延展追问：当前直接 import 页面组件有什么影响？
   - **答**：通过配置路由的 `component: () => import('@/views/Editor/editor.vue')` 实现。这会让 Vite 在打包时将该路由对应的组件及依赖拆分为一个独立的 JS Chunk，在用户访问此路由时才开始异步下载，大幅减少了首屏加载耗时。
47. 主问题：如果编辑器页面很大，路由层面如何优化首屏？延展追问：异步组件和代码分割怎么用？
   - **答**：在路由层面使用懒加载，并在组件内将大组件（如富文本、条形码生成库）用 `defineAsyncComponent` 进行异步加载；构建时通过 Vite 的 `rollupOptions` 将 node_modules 第三方大库（如 leafer-ui、ag-psd）做 splitChunks 拆包缓存。
48. 主问题：如果需要权限控制路由，你会怎么做？延展追问：路由守卫和组件内校验有什么区别？
   - **答**：可通过全局路由守卫 `router.beforeEach` 实现，在路由切换前检查 localStorage 或 Pinia 中的 Token 及用户角色。路由守卫支持全局拦截和重定向，能避免未授权的组件加载；而组件内校验则用于控制组件内部精细元素的展示与隐藏。
49. 主问题：如果编辑器路由需要携带模板 id，如何设计？延展追问：query 和 params 怎么选择？
   - **答**：推荐使用 query 传参（如 `/editor?id=123`）。因为 params 传参如果刷新页面，路由配置中若未定义 `:id` 占位，参数会丢失；且 query 具有更好的语义性，用户可以直接复制带 id 的链接分享，方便页面数据恢复。
50. 主问题：路由切换时编辑器如何销毁？延展追问：如果不销毁画布实例会有什么问题？
   - **答**：通过在组件 `onBeforeUnmount` 生命周期中显式调用 `editor.dispose()` 销毁画布。如果不手动销毁，Canvas 内部的事件监听（如 Resize, Click, Keydown）会一直存活在内存中，造成路由切换后的内存泄漏，并导致页面事件响应错乱。

### E. Vue 组件架构

51. 主问题：编辑器页面如何分区？延展追问：为什么分成 header、leftPanel、canvas、rightPanel、footer？
   - **答**： header 放置文件操作与导出，leftPanel 提供素材与图层管理，canvas 作为核心工作区，rightPanel 对应属性参数调整，footer 负责缩放比例等辅助功能。这契合专业设计软件布局，职责单一且方便用户使用。
52. 主问题：Vue 组件在项目中的职责是什么？延展追问：为什么不让组件直接管理全部画布状态？
   - **答**：Vue 组件主要负责渲染 UI、收集用户的交互输入、并在交互时调用具体的画布服务方法。不让组件直接管理画布状态，是为了实现“表现层”与“逻辑层”的解耦，防止 Vue 响应式代理大量画布实例对象导致极其卡顿。
53. 主问题：`editor.vue` 做了什么？延展追问：它为什么要在生命周期里创建 EditorMain？
   - **答**：editor.vue 是编辑器的根容器。它在生命周期（通常是 `onMounted` 之后 DOM 可用时）创建 `EditorMain` 实例，以初始化底层的依赖注入容器和服务；并在卸载时负责整体的生命周期清理与销毁工作。
54. 主问题：`canvasEdit.vue` 的核心职责是什么？延展追问：为什么要把 Leafer canvas DOM append 到 div？
   - **答**：canvasEdit.vue 核心职责是提供一个挂载画布的 DOM 容器（`<div ref="container">`）。它在 Mounted 时，将实例化好的 Leafer Canvas 真实 DOM 元素 append 到该 div 内，并监听容器大小变化以触发画布 resize。
55. 主问题：左侧素材面板如何添加元素？延展追问：为什么通过 `editor.add` 而不是直接操作 DOM？
   - **答**：左侧素材面板只负责展示素材列表，当点击时，通过编辑器提供的统一服务接口 `editor.add({ type: 'image', url })` 添加元素。这样可以让画布服务统一控制元素的位置、大小、默认图层 zIndex，并自动将其计入撤销恢复栈。
56. 主问题：右侧属性面板如何知道当前选中元素？延展追问：`activeObject` 为什么用 shallowRef？
   - **答**：编辑器服务通过 reactive/ref 将当前选中的对象暴露。因为选中的画布对象内部结构极其复杂，若使用普通 `ref` 会触发深层代理，严重影响渲染效率。所以使用 `shallowRef`，只在选中元素改变时触发第一层更新，即可让右侧面板获知。
57. 主问题：图层面板如何更新？延展追问：为什么需要 `childrenEffect()`？
   - **答**：当画布中的元素添加、删除或修改层级时，图层面板对应的树状列表需要更新。但由于画布对象非深度响应式，我们需要在事件监听中（如 ChildEvent.ADD）手动调用一次 `childrenEffect()`，通过重置图层列表的引用来强制 Vue 刷新图层视图。
58. 主问题：顶部工具栏一般负责哪些功能？延展追问：撤销、缩放、导出分别依赖哪些服务？
   - **答**：负责文件导入导出、撤销重做、保存模板、缩放控制等。撤销重做依赖 UndoRedoService，缩放依赖 MLeaferCanvas，导出依赖统一的 exportModal 服务。通过引入独立服务，工具栏组件只需要调用服务接口，自身逻辑非常轻量。
59. 主问题：组件之间如何通信？延展追问：props/emits、Pinia、事件总线、服务调用如何选择？
   - **答**：需要共享状态或联动修改时优先调用统一的单例服务（如 `editor.activeObject.width = value`）；如果是跨组件的解耦通知（如布局移动），使用 EventbusService 发送事件；只有小组件内部才使用 props/emits，从而降低组件树层层传递的耦合。
60. 主问题：如何避免组件越来越臃肿？延展追问：什么时候该抽 hook，什么时候该抽服务？
   - **答**：当组件中涉及异步网络请求、画布底层的交互计算或需要多个组件联动修改的状态时，应该将其抽离为独立的编辑器服务或 composable hook。原则是：UI 渲染留给组件，业务状态留给 Pinia/Hook，画布交互留给服务。
61. 主问题：为什么 `editor.vue` 使用 `onBeforeMount`？延展追问：如果用 `onMounted` 会有什么差别？
   - **答**：editor.vue 使用了 onBeforeMount 来尽早配置全局状态。如果使用 onMounted，子组件的挂载事件会先于父组件的 onMounted 触发，这可能导致子组件在初始化时，父组件尚未完成核心服务容器的创建，导致 useEditor 报错。
62. 主问题：为什么卸载时要 `dispose`？延展追问：事件监听不清理会造成什么问题？
   - **答**：卸载时必须调用 dispose 来手动解绑 window 上绑定的 resize 监听、keyup/keydown 快捷键监听以及 Leafer Canvas 本身的渲染事件。如果不清理，这些闭包引用的组件实例将永远无法被垃圾回收，导致页面内存溢出。
63. 主问题：`defineAsyncComponent` 适合什么场景？延展追问：异步组件加载失败怎么处理？
   - **答**：适合在首屏加载时不必须、且体积较大的模块（如富文本编辑弹窗、条形码/二维码生成库、PSD 解析 parser 模块）。如果加载失败，可以通过 defineAsyncComponent 的 onError 回调进行重试，或弹出友好提示告诉用户网络异常。
64. 主问题：组件样式为什么使用 scoped？延展追问：scoped 对深层子组件样式有什么限制？
   - **答**：scoped 会在当前组件的所有 DOM 节点上添加一个唯一的 `data-v-[hash]` 属性，并编译 CSS 选择器限制在当前组件内。限制在于它无法直接修改子组件（如 Arco 库组件）的内部样式，需要使用 `:deep()` 穿透修改。
65. 主问题：布局容器为什么要控制 overflow？延展追问：画布编辑器中的滚动和拖动画布如何避免冲突？
   - **答**：布局容器通过 `overflow: hidden` 防止页面出现浏览器级别的滚动条。海报设计器中的画布缩放和拖拽是基于 Canvas 视口矩阵变换实现的，如果不限制容器溢出，Canvas DOM 变大时会撑破页面，与画布内自身的拖拽发生冲突。

### F. 画布服务与 Leafer UI

66. 主问题：`MLeaferCanvas` 是什么？延展追问：为什么它是项目最核心的类？
   - **答**：MLeaferCanvas 是整个编辑器核心类，它直接持有 Leafer App 实例。它对上屏蔽了 Leafer 的底层 API，对下提供统一且简单的接口（如 add、remove、zoomTo、exportJSON），是所有组件操作画布的桥梁。
67. 主问题：Leafer `App` 在项目中代表什么？延展追问：它和 Vue app 是同一个概念吗？
   - **答**：Leafer App 代表画布的完整运行实例。它和 Vue app 完全不同：Vue app 是 Vue 框架用于管理 DOM 渲染和组件树的上下文；而 Leafer App 是独立的 Canvas 图形渲染引擎实例，用于绘制、管理和刷新画布上的矢量和像素图形。
68. 主问题：`contentLayer` 是什么？延展追问：为什么用 app.tree 作为内容层？
   - **答**：contentLayer 对应 Leafer 架构中的 `app.tree` 树状层，主要用于承载和组织用户所绘制的所有元素图层（如文本、图片、形状）。通过区分内容层，可以将编辑辅助线（控制点、标尺）独立开，避免混淆。
69. 主问题：`contentFrame` 是什么？延展追问：为什么用户元素要放在 Frame 里？
   - **答**：contentFrame 对应海报的实际大小视口（通常是一个 Frame 元素）。所有用户添加的可见图层都被挂载在 contentFrame 内。它是海报内容的真正边界，导出图片和序列化 JSON 都是基于 contentFrame 进行的。
70. 主问题：为什么创建底层白色画板？延展追问：如果没有底层画板会影响哪些功能？
   - **答**：白色底画板是 contentFrame 内最底部的 Rect 元素，用来模拟画布的白色底色。如果没有底画板，在导出 JPG 格式（不支持透明通道）海报时，背景会变成黑色，且用户也无法通过属性面板轻松修改海报的背景颜色。
71. 主问题：如何添加一个元素到画布？延展追问：`editor.add` 内部做了哪些额外事情？
   - **答**：添加元素时，`editor.add` 内部不仅调用 `contentFrame.add(element)`，还会自动为其注入唯一的 `id`（UUID），设置默认的坐标 `x`, `y`（使其位于画布正中心），计算其层级 `zIndex`，最后触发图层更新并向撤销恢复栈（UndoRedo）中压入一条“添加元素”的指令。
72. 主问题：如何选中一个元素？延展追问：为什么只有 activeTool 是 select 时才允许选中？
   - **答**：当用户点击画布元素时，系统会将其设为 `activeObject`。只有当 `activeTool` 是 `select`（选择工具）时才允许选中，这是为了防止当用户正在使用 `drag`（拖拽工具）或 `draw`（画笔/形状工具）时，点击画布误触元素的选择框，从而破坏当前的连续操作流程。
73. 主问题：如何取消选中？延展追问：为什么取消后默认选中 contentFrame？
   - **答**：可以通过点击画布空白处或调用相应方法取消选中，此时会把 `activeObject` 设为 `contentFrame`。默认选中 `contentFrame`（即画布本身）的目的是为了方便用户在没有选择任何具体元素时，右侧属性面板能自动展示画布的全局属性（如画布大小、背景色等）。
74. 主问题：如何实现画布缩放？延展追问：`zoomToFit` 和指定比例缩放有什么区别？
   - **答**：指定比例缩放是直接将视口缩放为固定百分比（如 100%, 150%）；而 `zoomToFit` 会计算 `contentFrame` 的大小和当前 DOM 容器大小的比例，自动调整缩放比例并居中对齐，保证整张海报画布能完美地、最大化地呈现在用户的可视区域内。
75. 主问题：如何让画布适配容器大小？延展追问：ResizeObserver 在这里起什么作用？
   - **答**：当浏览器窗口改变或编辑面板展开/折叠时，容器大小会发生变化。ResizeObserver 会实时监听画布挂载 DOM 容器的宽高变化，一旦变化就触发 `resize` 事件，重新计算视口中心并重绘 Canvas，保证画布始终不超出容器或发生变形缩水。
76. 主问题：为什么监听 ChildEvent.ADD 和 REMOVE？延展追问：这些事件如何驱动图层列表更新？
   - **答**：ChildEvent.ADD 和 ChildEvent.REMOVE 是 Leafer 内部的子节点变动事件。监听到这些事件时，表明画布上的图层有了增删，服务会触发 `childrenEffect()`，重新提取当前 contentFrame 内部最新的子元素列表，并赋值给 Vue 组件所绑定的响应式数组，从而触发图层面板列表的更新。
77. 主问题：为什么监听 PropertyEvent.CHANGE？延展追问：底层画布移动时为什么要发 layoutMoveEvent？
   - **答**：PropertyEvent.CHANGE 事件用于监听元素属性变化。当画布本身被用户平移、缩放或拖拽时，其位置属性发生改变，触发此事件；服务捕获后派发 `layoutMoveEvent` 事件，目的是通知外部的刻度标尺和对齐线组件实时更新位置刻度，保证辅助线和画布像素完美对齐。
78. 主问题：为什么监听 ResizeEvent.RESIZE？延展追问：第一次 resize 时为什么要设置 contentFrame 宽高？
   - **答**：第一次 resize 发生在画布刚刚挂载时。此时需要读取 container 容器的实际宽高，并将 `contentFrame`（海报视口）设置成预设的模板宽高（例如 800x1200），接着进行居中缩放。如果不进行这次初始化设置，海报尺寸会变成默认的 Canvas 大小，导致比例失调。
79. 主问题：为什么二维码要 lockRatio？延展追问：哪些元素应该锁定宽高比例？
   - **答**：二维码如果宽高比例失调（拉伸变形）会导致识别率下降甚至无法扫码。除了二维码，条形码、正圆、正方形以及某些特定图标也需要锁定宽高比例。通过在属性面板中限制 `lockRatio: true`，当修改宽度时，高度会等比例自动计算，确保其图形的结构有效性。
80. 主问题：如何根据 id 查找画布对象？延展追问：innerId 和业务 id 有什么区别？
   - **答**：根据 id 查找画布对象是使用 `contentFrame.findId(id)`。`innerId` 是 Leafer 引擎内部为每个实例自动分配的递增数字标识，而“业务 id”是我们自己通过 uuid 生成的唯一字符串。innerId 存在于内存中，每次重新导入 JSON 时都会改变，而业务 id 会随 JSON 导入导出被持久化，因此必须使用业务 id 关联业务属性。
81. 主问题：如何批量选中多个对象？延展追问：多选对属性面板有什么挑战？
   - **答**：通过鼠标框选或按住 Shift 多选，Leafer 会把选中的元素集合放入 `Editor` 的 `target` 数组（或创建临时 Group）。挑战在于右侧面板需要展示这些元素的公共属性（如 x, y, 颜色），如果它们属性不一致需要显示为“混合状态”或占位符，且对其批量修改时需要应用相对变换值。
82. 主问题：如何实现组内拖放？延展追问：`dropTo(group)` 的语义是什么？
   - **答**：当把元素拖入某个分组时，会执行 `group.add(element)`，即 `dropTo(group)`。它的语义是改变元素的父级容器（Parent Node），将元素从外层 Canvas 节点中剥离并挂载到组节点下，它的局部坐标会转换为相对于该组的相对坐标，以便用户能够随该组一起进行整体移动和缩放。
83. 主问题：为什么组和 Box 要绑定 DragDrop？延展追问：普通元素是否需要绑定？
   - **答**：组和 Box 绑定 DragDrop 事件是为了支持从外部（如左侧素材栏）拖拽图片并将其精准放置到该组/容器内部。而普通元素（如文字、简单形状）不需要支持作为容器承载其他子图层，因此不需要绑定 DragDrop 事件，只需保留基础的 drag 拖拽移动能力即可。
84. 主问题：画布对象为什么不直接深度响应式？延展追问：复杂对象被 Vue proxy 后可能有什么问题？
   - **答**：如果把 Leafer 画布对象变成深度响应式，Vue 3 的 Proxy 会递归代理对象的所有属性、原型方法和渲染缓存。由于画布对象非常庞大且存在自引用循环，这会导致 Vue 递归陷入死循环或消耗极高 CPU。此外，Vue 代理后的对象在 Leafer 引擎内部频繁渲染时会引起额外的隐式 setter/getter 损耗，导致严重卡顿。
85. 主问题：如何处理 Firefox 中 canvas display none 的问题？延展追问：浏览器兼容问题如何定位？
   - **答**：在 Firefox 中，如果 Canvas 元素的 `display: none`（或者其父容器 hidden），它的 `clientWidth` 会变成 0，导致缩放计算报错。定位这种兼容问题需要通过浏览器代理调试（User Agent），捕获特定浏览器的 DOM 属性异常，通过检测 clientWidth 是否为 0 或在挂载前改用 opacity 控制显隐来解决。

### G. 依赖注入设计

86. 主问题：项目为什么使用依赖注入？延展追问：不用依赖注入会怎样？
   - **答**：引入依赖注入是为了管理海量的解耦服务（如 Workspaces, UndoRedo, Layer, Keybinding 等）。如果不使用 DI，各个服务需要手动实例化并通过全局 import 互相引用，极易造成循环依赖，并且多个编辑器实例时无法做到服务状态的物理隔离，降低了代码的健壮性和可测性。
87. 主问题：`createDecorator` 做了什么？延展追问：它如何记录构造函数参数依赖？
   - **答**：`createDecorator` 接收一个唯一字符串服务 id，返回一个装饰器函数。该装饰器会被作为构造参数装饰器（如 `@IWorkspacesService`），利用 TypeScript 编译时生成的 `design:paramtypes` 元数据，将依赖的服务标识记录在被装饰类的构造参数列表中，以便在运行时按需解析依赖并注入。
88. 主问题：`IInstantiationService` 的作用是什么？延展追问：`createInstance` 和 `invokeFunction` 有什么区别？
   - **答**：`IInstantiationService` 是实例化服务的核心接口。`createInstance(ctor, ...args)` 接收一个类构造函数，自动分析该类的依赖并注入对应的服务单例，返回该类的实例；而 `invokeFunction(fn, ...args)` 则是运行一个自定义函数，并将容器服务作为参数传入，免去类构造的开销。
89. 主问题：ServiceIdentifier 是什么？延展追问：为什么服务 id 是函数而不是字符串？
   - **答**：ServiceIdentifier 代表服务的唯一标识，它其实是一个具有特殊属性的装饰器函数而不是普通字符串。使用函数的好处是可以完美契合 TypeScript 的类型系统，在使用 `@IService` 装饰构造参数时，IDE 能直接推断出被注入服务的具体接口类型，保证编译阶段类型安全。
90. 主问题：`ServiceCollection` 的作用是什么？延展追问：它如何保存服务描述符？
   - **答**：`ServiceCollection` 实质上是一个服务的注册表容器，内部用 Map 保存了“服务标识 (ServiceIdentifier)”到“服务实现或服务描述符 (Descriptor)”的映射。它提供了 `set` 和 `has` 方法，在容器启动或动态扩展插件时，用于注册新的服务实现。
91. 主问题：`SyncDescriptor` 是什么？延展追问：为什么不用直接 new 服务？
   - **答**：`SyncDescriptor` 是一个服务的同步描述符，它保存了服务的具体实现类（Class）和静态初始化参数，但不立即对其进行 `new` 实例化。它的作用是实现服务的懒加载（Lazy Initialization）：只有当其他模块真正声明并请求该服务时，DI 容器才会根据描述符去实例化它，优化首屏加载性能。
92. 主问题：`createChild` 有什么意义？延展追问：根容器和编辑器子容器如何分工？
   - **答**：`createChild` 用于创建一个子依赖注入容器。子容器会继承根容器的所有已注册服务，但也可以在子容器中覆盖注册局部服务。分工上，全局服务（如 http 请求、全局配置）放在根容器；而编辑器实例相关的局部状态服务（如 UndoRedo、画布实例）放在子容器中，实现多编辑器实例数据隔离。
93. 主问题：为什么 `EditorMain` 要创建子服务容器？延展追问：多编辑器实例时会有什么好处？
   - **答**：当页面中需要支持多个设计器（例如双画布对比、主副编辑区）时，由于多实例各自的选中对象、撤销历史和画布操作都是完全独立的，`EditorMain` 创建子服务容器可以确保这几个设计器实例之间的服务完全物理隔离，互不干扰，避免数据混乱。
94. 主问题：服务单例如何注册？延展追问：Eager 和 Lazy 实例化有什么区别？
   - **答**：单例服务在 `ServiceCollection` 中注册。Eager（饿汉式）是在容器初始化时立即对所有注册的服务进行 `new` 实例化；Lazy（懒汉式）则只保存 `SyncDescriptor`，直到被其它类注入请求时才执行实例化。设计器中对于大内存消耗、冷偏门服务通常采用 Lazy 注册以节省内存。
95. 主问题：依赖注入对测试有什么帮助？延展追问：如何 mock 一个服务？
   - **答**：在单元测试中，我们无需启动真实的 Canvas 和复杂的网络请求。通过依赖注入，我们可以在测试时创建一个 Test 容器，将实际的 `HttpService` 替换为一个只返回 Mock 数据的 `FakeHttpService`，或将画布渲染服务替换为 NullCanvas，从而可以独立、快速地测试各层业务逻辑。
96. 主问题：依赖注入有什么缺点？延展追问：新手维护时可能遇到什么困难？
   - **答**：缺点是调试和阅读源码的成本较高，对于不熟悉 DI 概念的新人来说，无法一眼看出某个服务在哪里被 `new` 出来的；另外，由于类构造参数被装饰器隐式处理，拼写错误或漏注册服务描述符会导致运行时报错，在排查时较为头疼。
97. 主问题：为什么 `MLeaferCanvas` 构造函数可以直接写 `@IWorkspacesService`？延展追问：装饰器在 TS 中如何工作？
   - **答**：`MLeaferCanvas` 使用了 TypeScript 实验性装饰器（Experimental Decorators）。在 TS 编译时，当解析到 `@IWorkspacesService` 装饰器时，编译器会将当前类的构造参数列表和注入标记输出到装饰器的 metadata 属性中，运行时 `InstantiationService` 读取这些参数即可把服务单例精准注入。
98. 主问题：服务之间循环依赖怎么办？延展追问：如何通过事件总线减少循环依赖？
   - **答**：循环依赖（如 A 依赖 B，B 依赖 A）会导致容器在解析类构造时陷入无限递归导致栈溢出。可以通过将直接依赖改为“事件通信”来解决，例如 A 中只抛出事件，B 监听该事件去调用 A 的方法，或者通过 `EventbusService` 作为中介进行消息解耦，彻底打断依赖环。
99. 主问题：依赖注入和普通 import 有什么区别？延展追问：什么时候普通 import 更简单？
   - **答**：普通的 import 是静态的、直接的依赖，在编译阶段被打包合并；而依赖注入是运行时解耦的依赖。如果是不涉及状态共享、职责单一的纯函数工具库（例如 `math.ts`），使用普通 import 更加简单高效；而涉及复杂交互、全局单例和多模块协作的业务模块才推荐使用 DI 容器。
100. 主问题：这个项目的 DI 风格像哪个大型项目？延展追问：VS Code 架构思想对前端项目有什么启发？
   - **答**：该项目的 DI 风格移植自 VS Code（Monaco Editor）的底层依赖注入架构。对前端项目的启发在于：对于高交互、多子系统协同的大型前端应用（如 IDE、低代码平台、编辑器），基于类和接口的“面向对象分层”和“控制反转（IoC）”能带来极强的代码拓展性和长期的可维护性。

### H. 事件总线与模块解耦

101. 主问题：为什么使用事件总线？延展追问：它解决了哪些模块耦合问题？
   - **答**：事件总线用于解决模块间的隐式强耦合。在编辑器中，有很多功能是“牵一发而动全身”的，例如修改背景色，需要同时更新画布、图层面板和历史记录。如果让颜色组件直接引入这些模块，代码会极度臃肿。通过事件总线，组件只需发布一个 `backgroundChange` 事件，其它模块各自订阅处理即可。
102. 主问题：`EventbusService` 有哪些事件？延展追问：哪些事件和多页面强相关？
   - **答**：`EventbusService` 中包含如 `workspaceChangeBefore`（工作区切换前）、`workspaceChangeAfter`（工作区切换后）、`activeObjectChange`（选中元素改变）、`layoutMoveEvent`（画布移动）等事件。其中 `workspaceChangeBefore` 和 `workspaceChangeAfter` 是和多页面数据同步最强相关的事件。
103. 主问题：工作区切换为什么分 before 和 after？延展追问：如果只发一个事件会有什么问题？
   - **答**：分 before 和 after 是为了在工作区切换的生命周期中进行精确的数据切片处理。如果只发一个事件，我们无法保证“在旧画布被清空之前”把当前的最新数据导出保存，也无法保证“在新页面 ID 更新之后”才开始载入新 JSON，容易导致数据丢失或恢复错乱。
104. 主问题：`workspaceChangeBefore` 做什么？延展追问：为什么要在切换前保存旧页面？
   - **答**：`workspaceChangeBefore` 在用户点击切换页面、尚未更新当前页面 ID 前触发。此时画布服务监听到该事件，会立即调用 `contentFrame.toJSON()` 导出现有画布的图层数据，并将其存入 WorkspacesService 的内存缓存中，防止用户的未保存编辑丢失。
105. 主问题：`workspaceChangeAfter` 做什么？延展追问：为什么切换后要恢复新页面 JSON？
   - **答**：`workspaceChangeAfter` 在页面 ID 已经成功切换到目标页面后触发。此时画布服务监听到该事件，会先清空当前的 Canvas 画布，然后根据目标页面 ID 从内存中取出之前保存的 JSON 数据，调用 `contentFrame.set(json)` 恢复图层，并重新调整画布缩放比例以适配屏幕。
106. 主问题：事件总线和 Pinia 有什么区别？延展追问：什么时候用事件，什么时候用状态？
   - **答**：Pinia 适合保存全局的“静态/动态状态值”（如当前用户、工具栏选中），并自动在 Vue 模板中保持响应式更新。而事件总线是“过程式/动作式”的，适合处理不一定要在模板中展示的命令行为（如“保存并清空画布”、“下载图片”），能够避免过多无用状态带来的响应式负担。
107. 主问题：事件总线有什么风险？延展追问：事件名写错如何发现？
   - **答**：风险在于事件名的维护比较松散，如果拼写错误会导致订阅失效且没有编译报错。另外，过度使用事件总线会导致“发布/订阅混乱”，使得一个操作触发数十个事件，让数据流向变得像迷宫一样难以调试。在本项目中，我们通过定义严格的 `Events` 枚举和 TS 类型映射进行了防范。
108. 主问题：如何增强事件总线类型安全？延展追问：Events 类型映射有什么作用？
   - **答**：通过定义一个包含所有事件名与对应载荷（Payload）类型的 TypeScript 接口（如 `export interface EventMap { 'activeObjectChange': IUI; ... }`），并在事件发布和监听方法中进行泛型限制，可以确保在 `emit` 或 `on` 一个事件时，IDE 能对事件参数进行类型检查和补全，规避手抖写错事件名或传错参数的风险。
109. 主问题：事件监听如何清理？延展追问：不清理会造成内存泄漏吗？
   - **答**：在事件总线中，监听事件通常会返回一个取消监听的函数（如 `unwatch` 或 `off`），我们在组件销毁或服务 dispose 时必须手动调用它。如果不清理，事件总线会一直持有这个订阅者的闭包引用，导致该组件即使从 DOM 中移除了也无法被垃圾回收，长期以往会造成严重的内存泄漏。
110. 主问题：事件总线会不会导致代码难追踪？延展追问：如何通过命名和日志降低维护成本？
   - **答**：如果滥用确实会导致调试困难。我们通过两个手段降低维护成本：一是严格限制事件的使用边界，只在跨模块的流程节点（如生命周期、画布重绘）使用事件；二是在 `EventbusService` 的基类中加入 Debug 日志开关，在开发环境下控制台会自动打印每个事件的触发时机和入参，一目了然。
111. 主问题：如果事件触发顺序错了会怎样？延展追问：如何保证关键流程顺序？
   - **答**：如果事件触发顺序出错，可能会导致“先载入新数据、后覆盖保存旧数据”的灾难。我们通过将异步事件包装为 Promise 的链式调用，或者在 `WorkspacesService` 内部集中管理主工作流，以命令模式排队执行 before 和 after 事件，从而确保流程在时序上的绝对正确。
112. 主问题：为什么布局移动事件要通过事件总线发？延展追问：标尺和辅助线如何监听它？
   - **答**：因为标尺（Ruler）和辅助线（Guides）组件是挂载在画布外层的独立 UI，它们需要精确得知画布内部的实际平移（translateX, translateY）和缩放比例（scale）来重绘自身刻度。通过在画布拖动时高频触发事件，让标尺组件订阅并局部更新，能有效避免全局 Vue 组件重绘带来的卡顿。
113. 主问题：事件总线可以替代所有组件通信吗？延展追问：为什么不建议滥用事件总线？
   - **答**：绝对不能。对于具有父子关系的组件，props/emits 依然是首选；对于涉及视图数据同步的状态，Pinia 是更好的选择。如果所有微小的通信（如按钮置灰）都通过事件总线处理，会导致系统中的事件漫天飞，代码可读性会急剧退化，维护成本极高。
114. 主问题：如何设计一个新的画布事件？延展追问：事件参数类型应该怎么定义？
   - **答**：设计新事件（例如 `elementLockChange` 元素锁定状态变化）时，首先需要在 `Eventbus` 的事件类型枚举中添加该事件名称，接着在 `EventMap` 接口中定义其携带的参数格式（如 `{ id: string, locked: boolean }`），最后在发布和监听处严格使用此泛型定义。
115. 主问题：如果多实例编辑器共用事件总线会怎样？延展追问：事件隔离如何设计？
   - **答**：如果多个编辑器共用一个全局事件总线，在一个画布上拖拽元素会导致另一个画布的标尺也跟着移动。设计隔离需要将 `EventbusService` 注册为子注入容器（Child Container）中的局部服务，让每个编辑器实例拥有自己独立的事件总线实例，实现物理隔离。

### I. 工作区与多页面

116. 主问题：WorkspacesService 负责什么？延展追问：工作区和页面是不是同一个概念？
   - **答**：`WorkspacesService` 主要负责维护页面列表（Id、标题、顺序）以及切换当前活动页面 ID。工作区（Workspace）和页面（Page）在本项目中概念一致，即海报模板的一个“画板页”。工作区服务负责组织页面元数据，而画布数据则存放在画布对应的 Map 里。
117. 主问题：为什么用 Map 保存页面 JSON？延展追问：Map 相比数组有什么好处？
   - **答**：使用 Map 可以用页面唯一的 uuid 作为 key，以页面 JSON 字符串或对象作为 value 进行高速读取和设置。Map 的读取时间复杂度为 O(1)，相比在数组中通过 `findIndex` 频繁遍历查找，不仅执行效率更高，代码也更清晰直观。
118. 主问题：新增页面时发生了什么？延展追问：为什么要同时创建空 JSON？
   - **答**：新增页面时，`WorkspacesService` 会生成一个新 uuid，并在页面列表数组中 append 该页面的元数据（如 `Page 2`）；同时，它会在画布的 Map 中以该新 uuid 为 key，初始化存入一个只包含背景底板 Rect 数据的空模板 JSON 结构，并自动切到该新页面。
119. 主问题：删除页面时发生了什么？延展追问：如果删除当前页应该切到哪一页？
120. 主问题：切换页面时如何保存旧页面？延展追问：为什么用 `contentFrame.toJSON()`？
   - **答**：切换页面前会调用 `contentFrame.toJSON()`，这能将当前画布视口内所有的子元素节点（图片、文字等）及其空间、属性参数转换为标准 JSON 数据。如果不调用此方法，用户切换页面再切回来时，当前的修改无法得到保留，会丢失所有的图层编辑状态。
121. 主问题：切换页面时如何恢复新页面？延展追问：为什么要 `contentFrame.clear()`？
   - **答**：恢复新页面时，必须先执行 `contentFrame.clear()`，因为 Canvas 只有一个，我们需要把旧页面的所有图形节点从画布树上彻底卸载，然后再通过 `contentFrame.set(json)` 导入并实例化目标页面的图形节点。如果不清空，旧页面的元素会堆积在新页面上。
122. 主问题：多页面导入 JSON 如何校验？延展追问：workspaces 和 pages 数量不匹配怎么办？
   - **答**：多页面 JSON 导入时，解析器会先校验 Schema：确保其含有 `pages` 数组且每个 page 的 id 在 workspaces 列表里有对应元数据。如果数量不匹配，会抛出 Schema 校验异常，并以第一个 page 的数据为基准进行修复和重置，防止渲染流程崩溃。
123. 主问题：为什么 `getPageJSON` 对当前页有特殊处理？延展追问：children 为什么要取最新响应式列表？
   - **答**：因为当前正在编辑的页面，其画布数据随时在发生更改（用户可能刚拉伸了某个矩形），Map 中保存的 JSON 是切换前的一刻状态，非最新。所以 `getPageJSON` 在获取当前页数据时，会实时调用一次 `contentFrame.toJSON()` 得到最新画布数据，从而保证导出的模板绝对最新。
124. 主问题：如何设计多页面导出数据结构？延展追问：页面顺序、封面、尺寸如何保存？
   - **答**：结构设计为一个大 JSON 对象：`{ width: 800, height: 1200, pages: [{ id: '1', title: '封面', layers: [...] }, { id: '2', title: '内页', layers: [...] }] }`。其中包含全局的分辨率尺寸、页面顺序数组以及各页具体的图层节点树，便于一次性完整恢复。
125. 主问题：如何实现页面缩略图？延展追问：导出缩略图会不会影响性能？
   - **答**：页面缩略图一般在切换页面或保存海报时触发。可以通过调用 Leafer 的 `toDataURL` 导出 base64 缩略图并存入 workspaces 列表中展示。为了防止性能问题，可以对导出操作进行防抖处理，或者降采样导出小图（如 100px 宽），避免大 Canvas 渲染阻塞主线程。
126. 主问题：如何处理页面切换时的选中状态？延展追问：为什么切换后要 discardActiveObject？
   - **答**：切换页面时，原画布的选中框（Transformer/Editor）会随着 Canvas 被清空而销毁。我们在切换前后必须调用 `discardActiveObject` 来清理 Vue 层的选中引用，防止右侧面板依然保留旧页面的图层属性造成跨页修改数据的 Bug。
127. 主问题：多页面中撤销恢复如何设计？延展追问：是全局历史还是每页历史？
   - **答**：支持多页面的撤销恢复通常有两种做法：全局历史栈和单页独立历史栈。本项目采用单页独立历史栈，即在 Map 中不仅保存页面的 JSON，还保存该页面专属的 Undo/Redo 历史记录。切换页面时，同时把撤销重做服务里的历史记录栈切换为当前页的独立栈，体验更好。
128. 主问题：多页面中字体加载如何处理？延展追问：是否需要提取全部页面字体？
   - **答**：不需要。在导入多页面模板时，只需先遍历解析第一页的图层，提取出第一页用到的网络字体进行下载并渲染；当用户真正点击切换到其他页面时，再懒加载对应页面专属的字体，从而极大优化首屏加载速度，减少无用字体下载。
129. 主问题：如果页面很多，JSON 存储会有什么性能问题？延展追问：如何做懒加载和增量保存？
   - **答**：如果多页面包含大量高分辨率图片，内存中的大 JSON 会导致浏览器内存占用飙升。可以通过懒加载和增量保存来优化：初始导入时只解析元数据和第一页，其他页面在切换到时才发请求加载具体 JSON，并且在保存时仅上传修改过的页面 JSON 数据。
130. 主问题：如何保证页面 id 唯一？延展追问：uuid 是否一定不会重复？
   - **答**：我们使用 RFC4122 标准生成的 UUID。UUID 是通过时间戳、随机数以及硬件 MAC 地址哈希计算生成的 128 位数字，其冲突概率在理论上小于几十亿分之一，对于纯前端单机及海量海报模板生成场景，可以完全视作绝对唯一，不会重复。

### J. 状态管理与响应式

131. 主问题：项目中 Pinia 管理了什么？延展追问：为什么 activeTool 适合放 Pinia？
   - **答**：管理轻量全局业务状态，如当前活动工具（activeTool，是选择模式还是钢笔模式）、当前画布缩放值（zoom）、侧边栏激活 Tab、系统内置的字体库列表等。 activeTool 适合放 Pinia 是因为多个组件（工具栏、画布、属性面板）都需要根据它联动更改交互方式。
132. 主问题：为什么不把 Leafer App 放 Pinia？延展追问：复杂实例进响应式系统有什么问题？
   - **答**：因为 Leafer App 包含了底层的 Canvas 画布 DOM 引用、WebGL 渲染上下文、事件管理器以及复杂的层级嵌套。放进 Pinia 会导致 Vue 使用 Proxy 对其进行上千个深层节点代理，不仅耗费巨量内存，还极易破坏 Leafer 的原型链方法调用，导致渲染报内部异常。
133. 主问题：`activeObject` 为什么用 shallowRef？延展追问：shallowRef 和 ref 的区别是什么？
   - **答**：`activeObject` 是指向当前选中图形实例的引用。使用 `shallowRef` 时，Vue 只会监听其第一层引用（即 `activeObject.value = newObj`）的变化，而不会监听其内部庞大属性的深层变动。这在保证 UI 面板能检测到“选中对象切换”的同时，规避了深度响应式劫持带来的巨大性能损耗。
134. 主问题：`ref._children` 的作用是什么？延展追问：为什么需要手动刷新数组？
   - **答**：`_children` 是画布节点（如 Frame/Group）内部的子元素数组，并非 Vue 响应式数组。为了让 Vue 层的图层列表能够响应图层的添加、删除和层级改变，当触发 ChildEvent 时，我们会执行 `ref._children = [...frame.children]`，通过替换整个数组引用的方式触发 Vue 更新图层视图。
135. 主问题：工具状态变化如何影响画布？延展追问：为什么非 select 工具要取消选中？
   - **答**：当 `activeTool` 发生变化（例如从 `select` 切换到 `draw` 形状画笔工具时），画布的 Transformer 选择框必须主动取消对当前元素的选中，将其置空，这是为了将画布交互状态重置为绘制状态，允许用户在画布上直接拖拽鼠标画出矩形，而不会误移已选元素。
136. 主问题：字体列表为什么放 Pinia？延展追问：多个组件共享字体状态有什么好处？
   - **答**：Pinia 适合作为全局字体状态的单一数据源。左侧的字体素材栏需要展示可用字体、右侧的文本属性面板需要供用户选择字体、而字体加载服务在下载网络字体后需要标记该字体状态为“已加载（loaded）”，这些组件通过 Pinia 共享状态，能避免数据不一致。
137. 主问题：computed 在手机号脱敏里起什么作用？延展追问：computed 和 watch 如何选择？
   - **答**：computed（计算属性）具有缓存机制，只有依赖项改变时才会重新计算，非常适合对手机号脱敏（如通过正则把中间四位替换为星号）等纯数据转换展示的场景。如果数据变化需要触发异步操作或主动修改外部状态，则应该选择 watch。
138. 主问题：watch activeTool 时要注意什么？延展追问：旧值在这里有没有用？
   - **答**：watch activeTool 时要确保在非 select 工具时及时销毁或隐藏选中框。在这里旧值（oldValue）非常有用，我们可以通过判断旧值，来针对性地清理上一阶段工具留下的临时画布辅助图形或监听事件，保证状态干净过渡。
139. 主问题：响应式状态和画布内部状态如何同步？延展追问：不同步会出现哪些 UI 问题？
   - **答**：画布内部的图形修改（如拖拽元素位置）是直接修改 Canvas 内存数据，并不会自动反映到 Vue 响应式数据中。如果不做同步，就会出现用户拉伸了元素，而右侧面板中输入的宽高值依然是旧值。所以我们需要在拖拽完毕后发事件，主动更新 Vue 响应式的 activeObject 副本值。
140. 主问题：如何避免响应式过度更新？延展追问：shallowRef、markRaw、debounce 分别适合什么场景？
   - **答**：shallowRef 适合用来保存只读或整体替换的重量级画布实例；markRaw 用于标记某些外部实例（如编辑器 core 核心），明确告诉 Vue 不要对其进行任何 Proxy 代理；debounce（防抖）则适合在用户频繁拉动滑块修改不透明度时，对画布的重绘和历史记录记录进行限频优化。
141. 主问题：markRaw 在 createCore 里有什么作用？延展追问：如果 core 被深度响应式化会怎样？
   - **答**：`markRaw` 可以将核心对象 `core` 标记为“永远不被 Vue 响应式化”。如果 `core` 包含极其庞大的依赖注入容器、各种复杂的全局服务以及画布底层引用，被 Vue 代理后会导致深度代理递归，引起极大的性能和内存损耗，甚至在调用底层方法时因为 this 指向 proxy 而报错。
142. 主问题：为什么 `childrenEffect` 先置空再赋值？延展追问：这和触发视图更新有什么关系？
   - **答**：因为 Vue 2/3 对数组的变化侦测是通过拦截数组变异方法或 Proxy 代理实现的。但由于画布 children 并不是响应式数组，直接修改数组内某一项的值不会触发 Vue 更新。通过先将数组清空 `ref.value = []`，再重新赋值最新的图层引用，可以通过完全替换引用的方式强制 Vue 的 UI 视图发生重绘更新。
143. 主问题：如何设计选中对象的属性双向绑定？延展追问：直接改对象属性会触发画布重绘吗？
   - **答**：双向绑定是通过在右侧面板的表单组件（如 input）上绑定选中的 `activeObject` 属性来实现的。直接修改对象的属性值（例如 `activeObject.width = value`）**会**立即触发 Leafer 的底层属性拦截机制，自动进行画布的局部脏重绘，不需要手动调用 render API。
144. 主问题：如何监听画布对象属性变化？延展追问：Leafer 的 PropertyEvent 可以解决什么？
   - **答**：Leafer 提供了 `PropertyEvent` 机制，可以监听画布上对象的属性变化（如 `width`, `height`, `x`, `y` 的变更）。当用户直接在画布上拖拽缩放某个元素时，服务通过监听 PropertyEvent 捕获属性修改，并实时同步更新 Vue 层的对应响应式属性值，保证 UI 面板数据同步。
145. 主问题：如果多个面板同时修改同一个对象，如何保证一致？延展追问：是否需要操作队列或事务？
   - **答**：为保证数据一致，修改操作需要收敛到画布服务提供的统一 API。如果多个属性面板在同一时刻高频修改同一个对象的同一个属性，虽然 Leafer 本身能处理最后一次修改，但为防止历史记录栈错乱，我们引入了防抖（debounce）控制，并在每次用户拖拽松开后触发一次合并的“事务修改”。

### K. 图层与层级管理

146. 主问题：图层管理的本质是什么？延展追问：为什么 zIndex 很重要？
   - **答**：图层管理的本质是控制画布上各个图形的**重叠绘制顺序（Render Order）**。`zIndex` 越大，表示该图层被绘制的时间越靠后，从而能够遮挡住 `zIndex` 较小的底部图层。如果 zIndex 混乱，会导致原本应该放在底部的背景图遮挡了最前方的文字内容。
147. 主问题：HierarchyService 做了什么？延展追问：为什么它是临时简单实现？
   - **答**：`HierarchyService` 负责计算和管理图层在页面层级树中的上移、下移、置顶、置底操作。它是简易实现的，因为它在移动层级时，是直接通过修改目标元素的 zIndex 数值并对当前层级列表重新进行升序/降序重排，未引入更复杂的自适应层级链表结构。
148. 主问题：如何获取顶层元素？延展追问：`_.last(items)` 的前提是什么？
   - **答**：获取顶层元素时，使用 `_.last(items)` 的前提是：必须保证传入的 `items` 图层数组**已经按照 zIndex 的大小进行了严格的升序排列**。只有在此前提下，数组中的最后一项才在视觉上处于最顶层。
149. 主问题：如何把元素上移一层？延展追问：previous/next level 如何计算？
   - **答**：要把元素上移一层，首先获取当前页面的所有同级图层并按 zIndex 升序重排，定位到当前元素的 index。然后，将当前元素与下一个相邻元素（index + 1）的 zIndex 值进行互换，并重新执行画布节点的深度刷新逻辑。
150. 主问题：如何把元素置顶？延展追问：zIndex 需要重新排序吗？
   - **答**：把元素置顶需要将它的 zIndex 设置为当前所有同级元素中最大的 zIndex + 1（或者重新计算一个更大的值）。不需要对所有元素重新排序，只需要直接将目标元素的 zIndex 修改并派发更新事件即可，但频繁置顶时需要防止 zIndex 值无限累加导致数值溢出。
151. 主问题：添加元素时为什么要设置 zIndex？延展追问：如果 zIndex 为空会怎样？
   - **答**：新添加元素时设置 zIndex 是为了确保它默认能够显示在最上层（即当前最大 zIndex + 1）。如果 zIndex 为空，根据 Leafer UI 的默认规则，它可能会采用默认值 0 或按节点插入顺序渲染，如果背景图的 zIndex 较大，新添加的元素就会被压入背景图下方而不可见。
152. 主问题：图层面板如何和画布 children 对应？延展追问：分组元素如何展示成树？
   - **答**：图层面板通过树形组件（如 `<a-tree>`）进行递归渲染。对于分组元素（Group），它的 children 属性下面会挂载其它的子图层节点，我们在构造树节点时，需要递归读取 Group 的子节点并封装为子 tree-node，从而在 UI 上呈现出可展开/折叠的层级树结构。
153. 主问题：删除元素时层级服务如何同步？延展追问：如果不同步会有什么问题？
   - **答**：删除元素时，层级服务需要同时在层级维护列表（Workspaces/Hierarchy）中移出该元素的引用。如果不同步，图层面板上依然会显示已删除的图层名字，而点击该图层时由于找不到画布中真实的实例，会导致控制台报空引用指针异常，造成编辑器卡死。
154. 主问题：多选元素调整层级有什么难点？延展追问：如何保持多选元素相对顺序？
   - **答**：难点在于，批量调整层级时，必须**保持这组选中元素内部的相对层级顺序不变**。例如同时选择层级为 1 和 3 的元素并上移时，不能将它们合并为同一个层级，而需要作为整体包结构向上偏移 zIndex。我们需要在移动前先对选中的元素按 zIndex 排序，再按顺序逐个位移。
155. 主问题：图层重命名如何通知 UI？延展追问：为什么有 layerRename 事件？
   - **答**：当用户在图层面板双击重命名一个图层时，需要调用 `element.name = newName` 修改画布对象名称，并主动派发 `layerRename` 事件，告诉其他订阅组件（如选区控制条、历史栈）进行名称更新，防止 UI 显示和画布数据脱节。
156. 主问题：隐藏图层如何实现？延展追问：不可见元素是否可选中？
   - **答**：隐藏图层可以通过将元素的 `visible` 属性设为 `false` 实现。隐藏后的元素在画布上是完全不可见的，并且为了符合交互直觉，不可见的元素是不允许在画布上通过鼠标直接点击选中的，用户只能通过左侧图层面板的眼睛图标来重新选中并开启显示。
157. 主问题：锁定图层如何实现？延展追问：锁定后是否允许属性面板修改？
   - **答**：锁定图层可通过将元素的 `locked` 属性设为 `true`，此时画布上的 Transformer 选择框将无法选中并操作它。锁定后，属性面板为了安全起见，通常也会将输入框置灰禁用，防止用户误修改导致排版混乱，必须由用户在图层面板手动解锁后方可编辑。
158. 主问题：组内层级和全局层级如何区分？延展追问：Group 内部 children 的 zIndex 如何处理？
   - **答**：在 Group 内部，子元素的 zIndex 是相对于该 Group 容器的，是**局部层级**。而 Group 容器本身相对于 contentFrame 拥有一个**全局层级**。绘制时，Leafer 引擎会先根据全局层级找到 Group，然后在 Group 内部根据子元素的局部 zIndex 依次渲染，实现了层级嵌套隔离。
159. 主问题：为什么 layer 服务不应该直接依赖 Vue 组件？延展追问：服务层和 UI 层如何解耦？
   - **答**：为了实现关注点分离（SoC）。如果 layer 服务直接操作 Vue 组件，那么在做跨平台（如 React 或 小程序）移植时，整个层级管理逻辑需要重写。通过让 layer 服务仅操作 Leafer 画布数据和通过事件派发，UI 层（Vue）只作为消费者订阅数据，实现了极高的分层解耦。
160. 主问题：如果 Leafer 后续优化 zIndex，你会如何调整项目？延展追问：如何降低第三方库变化影响？
   - **答**：通过在层级管理服务（`HierarchyService`）中把所有的层级操作（置顶、上移等）都收拢为统一的接口，外部业务组件不直接修改元素.zIndex。这样即使未来 Leafer 更改了 zIndex 的底层渲染逻辑，我们也只需要修改服务类的内部实现，业务代码完全不需要动。

### L. PSD 解析

161. 主问题：PSD 导入的完整流程是什么？延展追问：FileReader、readPsd、parser 分别做什么？
   - **答**：PSD 导入流程：1. 用户通过 `<input type="file">` 上传 `.psd`；2. 使用 `FileReader.readAsArrayBuffer` 读取为二进制；3. 使用 `ag-psd` 的 `readPsd` 方法解析生成 PSD JSON 数据树；4. 调用 `parser` 解析器模块中的 parseText, parseImage, parseGroup 逐个转换为 Leafer 实例并挂载。
162. 主问题：为什么 PSD 解析后还要转换对象？延展追问：PSD 图层和 Leafer 对象为什么不能直接等价？
   - **答**：PSD 文件的图层结构、度量单位、文字排版模型是 Photoshop 专有的，包含了许多前端浏览器无法直接渲染的参数。例如：PSD 中用 `styleRuns` 保存富文本，颜色可能带 CMYK 模式，描边参数命名也不同。如果不经过 parser 转换并重新计算映射，画布根本无法解析并绘制。
163. 主问题：普通文本和富文本如何区分？延展追问：styleRuns 代表什么？
   - **答**：判断 `layer.text` 下是否存在 `styleRuns` 数组。如果 styleRuns 存在且长度大于 1，说明文字内部不同部分有不同的样式（如字号、颜色、字体），必须识别为富文本；如果 styleRuns 缺失或只有一个，则直接识别为结构简单的普通文本（Text）图层。
164. 主问题：为什么富文本用 HTMLText？延展追问：HTMLText 相比 Text 有什么优势和风险？
   - **答**：HTMLText 允许在内容中混入 `<span style="...">` 标签，能完美还原 PSD 中 styleRuns 的局部字体大小、颜色等富文本特性。优势是表现力强，支持复杂的排版混排；风险是解析不规范的 HTML 可能会带来 XSS 注入风险，并且高频重绘 HTMLText 比普通 Text 性能开销更大。
165. 主问题：如何解析 PSD 字体大小？延展追问：transform 缩放对字号有什么影响？
   - **答**：PSD 文本图层中的真实字号等于 `text.style.fontSize` 乘以 `text.transform` 矩阵的平均缩放比（`scaleX + scaleY / 2`）。如果直接读取 fontSize，未考虑 transform 的矩阵缩放，解析导入后的字体大小会缩水数倍或变形。
166. 主问题：如何解析 PSD 颜色？延展追问：RGB、CMYK、透明度如何处理？
   - **答**：ag-psd 会解析出 `r, g, b` 对象，我们通过 [toRGBColorStr](file:///d:/项目相关/AAA/gzm-design/src/utils/color/g-color.ts#L1) 转换为 `rgb(r,g,b)` 字符串赋给 Leafer 的 fill 填充属性。CMYK 模式直接包含在图层颜色模式中，透明度（opacity）通常是图层的 `opacity / 255` 换算为 0 到 1 的数值应用。
167. 主问题：为什么当前提示不支持 CMYK？延展追问：如果要支持 CMYK，需要做什么？
   - **答**：因为 CMYK 颜色模式是为印刷设计的（青、品红、黄、黑），而浏览器的显示屏和 Canvas 引擎是基于 RGB 色彩空间（红、绿、蓝）工作的，无法直接还原 CMYK 像素色彩。如果要支持它，需要先使用数学公式（CMYK to RGB conversion）或引入色彩配置文件（ICC Profile）在前端进行像素级颜色空间转换。
168. 主问题：如何解析文字对齐？延展追问：PSD justification 和 Leafer textAlign 如何映射？
   - **答**：PSD 通过段落样式中的 `justification` 属性记录文字对齐（如 `left`, `center`, `right`, `justify-left` 等）。我们通过 [mapJustificationToTextAlign](file:///d:/项目相关/AAA/gzm-design/src/utils/psd/parser/text.ts#L182) 方法，将它们一一映射为 Leafer 中 [Text](file:///d:/项目相关/AAA/gzm-design/src/utils/psd/parser/text.ts#L61) 节点所支持的 `ITextAlign` 类型值。
169. 主问题：如何处理文字描边？延展追问：stroke position、opacity、fillType 如何转换？
   - **答**：PSD 中文字描边记录在 `effects.stroke` 数组中。我们遍历所有已启用的 stroke 选项，将其描边对齐方式 `position`、透明度 `opacity`、以及颜色 `color`（通常通过 r,g,b 对象转换）合并映射为 Leafer 组件所支持的 `stroke` 数组配置对象。
170. 主问题：如何处理文字下划线和删除线？延展追问：如果 Leafer 不支持同时存在怎么办？
   - **答**：PSD 通过 style.underline（下划线）和 style.strikethrough（删除线）布尔值定义。由于 Leafer 默认的 textDecoration 不支持同时存在两者，我们在 [setTxtStyle](file:///d:/项目相关/AAA/gzm-design/src/utils/psd/parser/text.ts#L248) 中进行了拦截取舍：当两者都存在时，优先使用下划线（设置 `textDecoration = 'under'`），以保障基础展示一致性。
171. 主问题：如何解析图片图层？延展追问：图片像素数据如何变成可显示 URL？
   - **答**：图片图层的像素数据在被 ag-psd 解析后会渲染到 layer.canvas 实例（即内存中的 HTMLCanvasElement）中。我们通过调用 `layer.canvas.toDataURL("image/png")`，把 canvas 的二进制像素导出为一串 Base64 格式的 URL 字符串，然后赋予 Image2 的 url 属性进行显示。
172. 主问题：如何解析分组图层？延展追问：PSD group 和 Leafer Group 有哪些属性差异？
   - **答**：PSD 中的组在解析后拥有 children 数组、隐藏状态、zIndex。而 Leafer 的 Group 除这些之外，还需要设定 `draggable: true` 允许拖动，且其宽高需要通过 `layer.canvas` 或者子图层范围动态计算赋予，使得组在画布中拥有正确的包围盒以进行碰撞检测。
173. 主问题：如何处理蒙版？延展追问：剪切蒙版和普通遮罩有什么区别？
   - **答**：在 [parseMask](file:///d:/项目相关/AAA/gzm-design/src/utils/psd/parser/mask.ts#L15) 中，我们拿到一个 clipping 数组，其中最后一项作为蒙版页（Mask Layer），其上的图层作为依托在蒙版上的填充图层。我们通过将蒙版图层的属性设为 `layerMask.mask = 'clipping'`，然后将它们放进同一个 Group 内，从而实现了剪切蒙版效果。
174. 主问题：PSD 导入后为什么要加载字体？延展追问：字体缺失会导致哪些视觉偏差？
   - **答**：即使图层属性都解析正确，如果用户本地和系统未安装该 PSD 所采用的特有字体（如思源黑体），浏览器就会使用默认的宋体或微软雅黑渲染，这会导致文字宽度变化，产生排版移位、断行甚至溢出画布的视觉偏差。因此必须根据字体名提取并异步载入对应的 WOFF/TTF 文件。
175. 主问题：PSD 解析性能如何优化？延展追问：大 PSD 文件是否应该使用 Web Worker？
   - **答**：大 PSD 文件的 ArrayBuffer 解析是 CPU 密集型任务，放在主线程执行会导致浏览器 UI 冻结。可以通过 Web Worker 来优化：把 FileReader 读出的 ArrayBuffer 传送给 Worker 线程，在后台调用 ag-psd 进行计算，解析生成无循环引用的 JSON 后再传回主线程渲染。
176. 主问题：PSD 导入失败如何提示用户？延展追问：错误信息如何做到业务友好？
   - **答**：使用 try...catch 包裹核心解析代码。针对已知的局限（如 CMYK 色彩模式，或者文件大于 100MB 导致 OOM），捕获特定的 Error 字段（如 `Color mode not supported: CMYK`），并向用户弹出明确、易懂的友好中文提示（如“暂不支持CMYK色彩模式的文件，请先使用PS转换为RGB”），而不是打印一堆乱码报错。
177. 主问题：PSD 图层顺序如何映射？延展追问：zIndex 如何保证和 Photoshop 一致？
   - **答**：Photoshop 的图层数组在数据源里是**自顶向下（从最上层到最底层）**排列的，而 Canvas 渲染引擎的 children 树则是**自底向上（先进先出，最底部的先绘制）**排列。因此，在 [parseLayers](file:///d:/项目相关/AAA/gzm-design/src/views/Editor/layouts/header/left/fileOper.vue#L162) 中解析时，我们首先使用 `layers.reverse()` 反转数组，以保证 zIndex 顺序符合直觉。
178. 主问题：PSD 中智能对象如何处理？延展追问：为什么智能对象比较难？
   - **答**：智能对象图层在 PSD 中是一个独立嵌套的嵌入文档或外部链接，它可能经过了复杂的透视变形和栅格化处理。浏览器端很难直接还原智能对象内部的图层编辑逻辑，通常做法是将其作为普通的已渲染位图（静态图片）直接提取出 canvas 进行渲染。
179. 主问题：PSD 特效如何处理？延展追问：阴影、渐变、混合模式转换有什么难点？
   - **答**：难点在于 PS 的特效（如斜面浮雕、投影、内发光）是通过复杂的渲染算法在图层像素上实时叠加的，Leafer 等 Canvas 2D 库只支持简单的 box-shadow。对于这些特效，通常只能转换为 Leafer 的内置 shadow 属性，对无法还原的复杂渐变或特效则采取栅格化为图片的降级方案。
180. 主问题：如何测试 PSD 解析准确性？延展追问：用截图对比还是 JSON 对比？
   - **答**：测试准确性通常有两种做法。快照测试（Snapshot Test）通过比对解析后导出的海报 JSON 结构与已知正确的基准 JSON；而为了防范渲染还原度偏差，更严格的回归测试通常使用像素级截图对比（Pixelmatch 库），比对画布渲染出的图片像素和原 PSD 导出的 PNG 像素的相似度。

### M. 字体与富文本

181. 主问题：为什么字体加载是设计器的重要问题？延展追问：字体未加载时文本尺寸会不会变化？
   - **答**：因为字体在 Canvas 绘制中是极其重要的元数据。在字体文件尚未加载完成时，浏览器会临时使用系统默认字体计算文字的包围盒大小；当网络字体突然下载完成并应用时，文字宽度变大，就会导致文字出现排版换行错乱、重叠等严重的设计偏差。
182. 主问题：fontStore 做了什么？延展追问：默认字体为什么可以跳过加载？
   - **答**：`fontStore` 保存了系统中所有的网络字体和常用系统内置字体。对于系统默认内置字体（如 Arial, sans-serif），由于系统出厂自带，我们直接在 store 中将其标记为 `loaded` 状态，跳过网络下载流程，直接触发画布重绘即可，避免了重复发送 HTTP 请求。
183. 主问题：为什么从模板 JSON 提取字体？延展追问：如何同时提取 Text 和 HTMLText 的字体？
   - **答**：因为保存的模板 JSON 中，只有文本图层（Text、HTMLText）知道自己所采用的 `fontFamily` 到底是什么。我们在渲染海报模板前，会先写一个递归搜索算法，从该 JSON 的图层树中筛选出所有文本图层，提取它们用到的 fontFamily 集合，存入待加载队列。
184. 主问题：HTMLText 的字体如何解析？延展追问：正则解析 CSS 有什么风险？
   - **答**：HTMLText 的字体信息是直接内联在 HTML 内容的 `style="font-family: '...';"` 中的。我们通常使用正则表达式（如 `/font-family:\s*['"]?([^'";
]+)['"]?/gi`）去提取 style 属性里的字体名称。风险在于，如果 HTML 字符串结构极其复杂或者带有嵌套样式，正则可能漏匹配或匹配错字体名。
185. 主问题：为什么使用 FontFaceObserver？延展追问：它和直接注入 @font-face 有什么区别？
   - **答**：FontFaceObserver 是一个基于 CSS Font Loading API 封装的监听库。它通过在内存中创建测试字符（如大写的 'BES'），并高频检测当应用指定 fontFamily 后该字符宽度是否发生突变来精确感知字体是否加载成功；而直接注入 @font-face 只能将 CSS 插入 DOM，无法通知 JS 什么时候字体真正下载并渲染完毕。
186. 主问题：字体加载为什么要并发控制？延展追问：并发太高会有什么问题？
   - **答**：若一次性并发请求下载数十个字体文件（每个文件可能 3MB+），会严重耗尽浏览器的 TCP 连接通道和网络带宽，导致其它素材接口请求出现挂起和超时，引起页面卡顿。因此需要使用队列（Promise Pool）进行并发控制，将最大并发数限制为 3，依次平滑下载。
187. 主问题：字体加载失败如何处理？延展追问：是否应该阻塞模板渲染？
   - **答**：字体下载因断网或跨域失败时，在超时（如 3000ms）后不应该无限期阻塞页面。系统会抛出超时异常并在控制台记录，接着将该字体状态置为“已加载（loaded）”，降级使用系统默认备用字体渲染画布，以保障用户依然能够看到海报并进行编辑，不至于卡死在 loading 面板。
188. 主问题：加载字体后为什么要 forceRender？延展追问：不重新渲染会怎样？
   - **答**：在网络字体下载完成后，Leafer 引擎并不会自动检测并立即重绘画布上的文本，导致页面文字依然是默认宋体。我们必须显式调用 `canvas.forceRender()` 或 `canvas.contentFrame.childrenEffect()`，强制 Canvas 进行全局重新渲染以应用新字体的字形。
189. 主问题：富文本和普通文本属性编辑有什么区别？延展追问：富文本局部样式如何编辑？
   - **答**：普通文本修改是修改整体的 fontFamily、fontSize 和 fill；而富文本编辑允许针对某一段字符进行加粗、标红等。编辑富文本需要在页面中挂载一个与 HTMLText 图层绝对定位重叠的富文本编辑器输入框（如 TinyMCE/Quill），当输入框中发生富文本内容编辑时，将生成的富文本 HTML 实时反馈给 HTMLText。
190. 主问题：TinyMCE 在项目中可以承担什么角色？延展追问：如何把 TinyMCE 内容同步到 HTMLText？
   - **答**：TinyMCE 充当了“富文本编辑框”的角色。在用户双击 HTMLText 图层时，系统会弹出一个包含 TinyMCE 的对话框，并将 HTMLText 图层内部的 HTML 文本传入。在用户编辑、修改样式后，将 TinyMCE 导出的最新 HTML 字符串通过 setter 重新赋值给 HTMLText 图层的 text 属性，并强制重绘。

### N. 导入导出与数据格式

191. 主问题：为什么模板保存为 JSON？延展追问：JSON 保存相比图片保存有什么优势？
   - **答**：相比图片导出，保存为 JSON 能够完美保留所有图层（Text, Image, Shape）的矢量编辑属性、坐标位置和原始数据。用户可以在下次打开海报时继续随意移动、编辑文本或更换图片，而图片保存后图层全部丢失合并，无法再进行精细化的二次修改。
192. 主问题：`contentFrame.toJSON()` 有什么作用？延展追问：导出的 JSON 是否包含方法？
   - **答**：`contentFrame.toJSON()` 会遍历当前海报视口下所有的子图层实例，将其序列化为一个标准的 JS 对象，包含各节点的类型（`tag`）、尺寸、相对坐标、颜色、图片地址等。导出的 JSON **不包含**任何 JavaScript 原型方法，只包含纯数据属性，可以直接序列化为字符串存储。
193. 主问题：`contentFrame.set(json)` 有什么作用？延展追问：JSON 恢复时自定义元素如何识别？
   - **答**：`contentFrame.set(json)` 是通过读取 JSON 数据来反序列化重绘画布。Leafer 引擎会解析 JSON 中的 `tag` 字段（如 `Image2`），去注册好的 UI 列表中查找对应的类进行 new 实例化。如果遇到未注册的 tag，Leafer 将无法识别，因此我们必须在 main.ts 中提前注册自定义组件。
194. 主问题：导入 JSON 时为什么要 clearHistory？延展追问：导入模板后撤销栈应该如何处理？
   - **答**：因为导入新模板意味着重新载入了一个全新海报，之前的撤销恢复栈里记录的所有“移动图层”、“修改颜色”等步骤都是针对旧海报图层 ID 的。如果不清空历史记录栈，用户一旦点击“撤销”，就会尝试去操作已经销毁的旧图层实例，导致运行时报错。
195. 主问题：导入 JSON 后为什么要 zoomToFit？延展追问：用户体验上有什么意义？
   - **答**：导入 JSON 模板后执行 `zoomToFit`，能够保证不同尺寸的海报模板（比如 800x1200 的竖版海报或 1920x1080 的横版海报）在进入编辑器后，都能自动适配当前屏幕容器的大小，并居中完整展示，避免了因大尺寸导致海报只显示一个局部角落，优化了初始视觉体验。
196. 主问题：多页面 JSON 应该包含哪些字段？延展追问：workspaces、pages、cover、scale 如何设计？
   - **答**：多页面 JSON 应该设计为：`{ workspaces: [{ id: 'page-1', name: 'Page 1', order: 0 }], pages: { 'page-1': { tag: 'Frame', width: 800, height: 1200, children: [...] } }, currentId: 'page-1' }`。不仅包含页面数据，还包含页面元信息、当前激活页面 ID 以及缩放值等，便于一次性导入还原。
197. 主问题：图片导出如何实现？延展追问：导出整个画布和指定元素有什么区别？
   - **答**：图片导出是调用 Leafer 提供的 `export` 接口。导出整个画布是基于 `contentFrame` 进行截取，只导出海报可视范围内的内容；而导出指定元素（如只导出里面的某个图片或二维码）则是基于该元素自身的 boundingBox 进行裁切，两者的尺寸和输出内容完全不同。
198. 主问题：导出 PNG、JPG、WEBP 有什么差异？延展追问：透明背景应该用哪种格式？
   - **答**：PNG 支持透明通道，适合保存带有透明背景的免抠海报或贴纸素材；JPG 压缩比高，文件体积小，但不支持透明背景（透明部分会变白色），适合保存满版彩色运营海报；WEBP 在保证画质的同时体积最小，但需要考虑部分老旧浏览器的兼容性。
199. 主问题：导出时如何处理跨域图片？延展追问：canvas taint 是什么？
   - **答**：当画布中绘制了来自外部第三方域名的图片（且没有配置 CORS 跨域响应头），一旦 Canvas 尝试读取该图片的像素（例如执行 `toDataURL` 导出图片），浏览器会由于同源策略（SOP）保护触发 "Canvas tainted" 错误，禁用导出。解决办法是让图片服务配置 `Access-Control-Allow-Origin: *`，并在图片元素上声明 `crossOrigin = 'anonymous'`。
200. 主问题：导出大图时如何优化？延展追问：像素比和内存占用有什么关系？
   - **答**：导出大图（如 300dpi 印刷图）需要将像素比（pixelRatio）设置为 2 到 3，导致 Canvas 像素暴增。优化策略包括：1. 导出前临时移除不必要的辅助线渲染以节省图层渲染开销；2. 导出时使用离屏 Canvas（OffscreenCanvas）在后台线程渲染导出；3. 使用 Canvas 的 toBlob 异步切片导出，减少内存瞬间峰值占用。

### O. 请求、Mock 与后端交互

201. 主问题：Axios 拦截器做了什么？延展追问：为什么 blob 和 arraybuffer 要直接返回？
   - **答**：Axios 拦截器用于处理请求头注入、统一报错逻辑等。因为下载导出的图片或读取 PSD 文件需要原始的 `blob` 或 `arraybuffer` 类型二进制数据，如果按照普通 JSON 数据去解析反序列化会报解析错误。因此需要在拦截器中拦截响应的 `responseType`，遇到这类二进制类型时直接放行返回，保留原始流数据。
202. 主问题：统一响应结构有什么好处？延展追问：`success`、`code`、`msg`、`data` 如何使用？
   - **答**：统一响应结构（如 `{ code: 200, data: ..., msg: 'success' }`）使得前端能够用一套标准拦截逻辑去规范处理成功和失败，简化了状态码解析工作。通过 `code === 200` 识别业务成功，而当业务报错时可以直接通过 `msg` 提示给用户，提高了前后端协作的确定性。
203. 主问题：接口失败时如何提示？延展追问：Message.error 是否适合所有错误？
   - **答**：在接口报错时，通常通过全局 Toast/Message 提示错误信息。但 `Message.error` 并不适合所有错误（如 401 未登录需要直接静默跳转登录，或者大文件上传失败需要支持暂停和重试而不是生硬报错），必须针对不同的 HTTP 状态码和业务码进行分流处理。
204. 主问题：401 为什么要跳转登录？延展追问：如果在组件外使用 useRouter 有什么风险？
   - **答**：当拦截到 401 状态码时，说明登录凭证失效，必须立即清空本地 Token 并重定向至登录页。在组件外部（如 Axios 拦截器中）无法直接使用 Vue 组件特有的 `useRouter()` 钩子，因为 useRouter 必须运行在 setup 内部；我们需要直接引入 `src/router/index.ts` 导出的全局 `router` 实例进行跳转。
205. 主问题：mock 数据如何帮助开发？延展追问：mock 数据和真实接口不一致怎么办？
   - **答**：Mock 数据可以让前端在后端 API 未就绪时，独立调试列表、模板加载等交互。如果 Mock 数据与真实接口字段不一致，可以通过编写拦截代理适配层（Adapter Pattern），或者在发现字段变更后，第一时间拉取最新的 Swagger/Yapi 生成最新的接口 TypeScript 声明并修改 Mock 内容。
206. 主问题：素材列表接口如何分页？延展追问：noMore 如何判断？
   - **答**：素材列表的分页基于滚动加载或分页器组件。在请求时传递 `page` 和 `pageSize` 参数，根据后端返回的 `total` 字段与当前累计加载的素材数量进行比对：当 `currentCount >= total` 时，设置 `noMore = true`，停止高频滚动触发，避免无用 API 请求。
207. 主问题：上传文件接口要注意什么？延展追问：大文件、断点续传、进度条如何做？
   - **答**：上传大体积的 PSD 文件或高分辨率素材时，为防止网络波动导致上传失败，通常需要支持：1. 分片上传（将大文件分割成多个 2MB 的 Blob 片段并行上传）；2. 断点续传（上传前调用接口检查已上传的切片序号）；3. 监听 Axios 的 `onUploadProgress` 回调，实时展示百分比进度条。
208. 主问题：字体接口如何缓存？延展追问：localStorage 版本号有什么作用？
   - **答**：为防止重复下载几兆大小的网络字体，我们使用 `localStorage` 缓存已下载的字体 Base64 数据或将字体文件缓存在浏览器的 IndexedDB/Cache Storage 中。通过在接口返回时对比字体库的“版本号（version）”，如果版本号未变则直接从本地缓存读取，发生更新时才清除旧缓存并重新下载。
209. 主问题：模板接口返回 JSON 后如何进入画布？延展追问：接口数据需要校验吗？
   - **答**：模板接口返回海报 JSON 后，首先必须通过 JSON Schema 规则进行白名单和字段校验（防止恶意注入或缺失核心宽高等破坏性数据），校验通过后再执行 `canvas.contentFrame.set(json)`，紧接着触发 `zoomToFit` 调整自适应视口大小，并将此行为计入历史初始化栈。
210. 主问题：如何处理 API baseURL？延展追问：前端环境变量能否存敏感信息？
   - **答**：API `baseURL` 通常根据开发环境（`development`）和生产环境（`production`）在环境变量 `.env` 中配置。前端环境变量**绝对不能**存储敏感信息（如数据库明文密码、云服务的私钥），因为打包编译后的静态资源是完全暴露在客户端浏览器中的，任何人都可以直接查看。

### P. 性能优化

211. 主问题：在线设计器有哪些性能瓶颈？延展追问：元素数量、图片大小、字体加载、PSD 解析分别如何影响性能？
   - **答**：瓶颈主要在于：1. 元素数量过多（导致 Canvas 渲染树过深，包围盒计算变慢）；2. 大图未压缩（瞬间耗尽 WebGL 纹理内存导致浏览器崩溃）；3. 字体加载卡顿（导致排版重构，阻塞主线程）；4. PSD 解析（复杂的图层计算和二进制解析引起 CPU 暴涨）。
212. 主问题：为什么使用 shallowRef 和 markRaw？延展追问：它们如何减少响应式开销？
   - **答**：在项目中，我们使用 `shallowRef` 来保存当前选中的元素 `activeObject`，防止其子属性被深度劫持；使用 `markRaw` 标记整个 `core` 编辑器核心上下文实例。这两种做法可以让庞大、多层循环引用的画布组件绕过 Vue 的深度依赖收集系统，将渲染性能提升数倍，杜绝因响应式导致的打字和移动卡顿。
213. 主问题：PSD 解析如何避免阻塞主线程？延展追问：Web Worker 如何改造？
   - **答**：PSD 的二进制字节解析和图层展开是非常耗费 CPU 的计算过程，放在主线程执行会直接导致浏览器界面假死。可以通过 Web Worker 优化：在主线程将 PSD 的 ArrayBuffer 作为可转移对象（Transferable Objects）传给 Worker 线程，在后台解析完成后再将结构化的 JSON 数据传递回来，保证主线程交互绝对流畅。
214. 主问题：素材图片列表如何优化？延展追问：懒加载和瀑布流如何减少首屏压力？
   - **答**：对于素材面板中的海量图片，我们采用：1. 图片懒加载（仅当图片滚动到可视区域内时才加载真实的 src）；2. 瀑布流自适应布局并结合虚拟列表（Virtual List）渲染技术，只渲染可视区域内的素材卡片 DOM，将 DOM 节点数量控制在极低水平，避免首屏卡顿。
215. 主问题：画布 resize 频繁触发怎么办？延展追问：是否需要 debounce？
   - **答**：当用户拖拽调整浏览器窗口大小时，`resize` 事件会被频繁、高频地触发（一秒钟几十次），导致画布视口矩阵不断重构。我们需要使用 `debounce`（防抖）或者 `throttle`（节流）函数进行控制，将触发频率限制在 100ms 左右，保证窗口缩放过程顺滑且不产生内存溢出崩溃。
216. 主问题：属性面板频繁修改如何优化？延展追问：拖拽时是否应该实时保存历史？
   - **答**：当用户频繁拖拉滑块（如修改元素 X 坐标）时，我们只实时更新画布的渲染视图（直接修改 `element.x = value` 属性触发底层重绘），而将“向 UndoRedo 栈压入历史记录”以及“触发 Pinia/API 数据上传”的操作用 `debounce` 进行延迟合并，仅在拖拽松开（dragend）时保存最终状态，防止撤销栈爆满且性能下降。
217. 主问题：撤销恢复栈过大会怎样？延展追问：如何限制历史记录大小？
   - **答**：撤销重做栈如果无限度存储每一次属性变更，会导致内存中积压成百上千个庞大的画布 JSON 快照，最终造成浏览器内存泄漏（OOM）。优化手段是设置历史记录的最大长度限制（如最大 50 条），并在历史栈达到上限时，自动踢出最底部的旧快照，控制内存占用。
218. 主问题：多页面很多时如何优化切换？延展追问：是否需要页面 JSON 懒加载？
   - **答**：当海报模板包含很多个画板页面时，一次性把全部页面的 JSON 和大图都加载进来会极大拖慢首屏。我们采用多页面懒加载：初始化时只下载第一页的数据并渲染，其他页面的详细 JSON 仅在用户真正点击对应的缩略图切页时，才发送 API 请求动态拉取并进行初始化渲染。
219. 主问题：导出大图为什么可能卡顿？延展追问：如何做导出进度提示？
   - **答**：因为导出大图需要临时创建超大分辨率的 Canvas 并渲染极高像素的位图，这会瞬间吃满 GPU/CPU 算力。为了优化用户体验，我们应该在导出前弹出一个全局 Loading，并结合 Web Worker 或切片分步渲染，为用户提供一个明确的“正在导出中... (XX%)”的进度提示，避免用户误以为页面假死。
220. 主问题：字体加载并发为什么设为 3？延展追问：并发数如何选择？
   - **答**：字体下载并发控制为 3。如果并发数过高（如 10+），会瞬间占满浏览器的最大并发 HTTP 连接数，导致主页面其它的关键 API 请求（如保存、素材获取）处于挂起超时状态，降低整体稳定性；过低则导致字体下载太慢。实践表明，3-4 个并发能兼顾带宽和核心 API 的响应速度。

### Q. 插件化与扩展性

221. 主问题：项目插件系统如何工作？延展追问：core.use 和 editor.use 有什么关系？
   - **答**：项目的插件系统采用微内核架构。`core.use(plugin)` 会调用插件的 setup 方法，并在 `editor.use` 阶段将当前的实例化服务容器上下文注入。插件可以通过容器获取 `IEventbusService` 等服务，从而在不修改编辑器主包代码的前提下，以完全解耦的方式定制开发新的形状或操作面板。
222. 主问题：插件上下文包含什么？延展追问：为什么要传 service 和 use？
   - **答**：插件上下文（Plugin Context）包含当前编辑器的服务定位器（`ServiceLocator`）以及配置参数。为什么要传 service？因为插件需要通过它获取快捷键、层级、事件总线、画布实例等所有核心服务的引用，从而能调用主系统的 API 实现诸如“保存前进行抠图”等功能。
223. 主问题：插件生命周期有哪些？延展追问：setup 和 dispose 分别做什么？
   - **答**：插件具有 `setup`（安装/初始化）和 `dispose`（卸载/销毁）两个核心生命周期。在 `setup` 中，插件会完成事件监听绑定、UI 插槽挂载、快捷键注册；在 `dispose` 中，插件必须彻底解绑所有事件、释放内存中创建的临时图形节点，防止插件卸载后造成严重的内存泄漏。
224. 主问题：插件插槽有什么作用？延展追问：如何让插件扩展工具栏或面板？
   - **答**：插槽是插件用于扩展 UI 层的机制。例如，通过在右侧属性面板或顶部工具栏预留插件插槽（`<slot name="toolbar-plugin">`），插件在 setup 时可以动态向插槽中注入自定义的按钮（如“AI智能抠图”），从而无缝扩展编辑器的功能版面。
225. 主问题：为什么插件实例用 Symbol 作为 id？延展追问：Symbol 有什么特性？
   - **答**：使用 `Symbol`（如 `Symbol('AIEraser')`）作为插件的唯一 ID，是因为 Symbol 具有绝对唯一性，不会和编辑器内置的其他插件或未来第三方引入的插件名称发生字符串冲突，能够确保插件集合在 Map 中的 key 安全，不会发生错位覆盖。
226. 主问题：插件安装为什么用 runWhenIdle？延展追问：浏览器空闲调度有什么意义？
   - **答**：有些非核心功能的插件（如水印、二维码辅助插件）并不需要在首屏初始化时立即加载。使用 `requestIdleCallback`（`runWhenIdle`）可以利用浏览器渲染帧的空闲时间段再去平滑安装这些插件，避免了它们在首屏渲染关键阶段抢占主线程算力，极大优化了设计器冷启动速度。
227. 主问题：如果要新增 AI 抠图插件，你会如何设计？延展追问：它需要哪些服务能力？
   - **答**：设计 AI 抠图插件时：首先，在 setup 中获取 `IEventbusService` 和 `MLeaferCanvas`。监听用户的右键菜单或面板点击事件；当触发时，获取当前选中的 Image2 对象并将其图片 base64 传给后端 AI 抠图接口；最后，将返回的带透明通道的 PNG 图像重新更新到画布选中图层上。
228. 主问题：如果要新增图片滤镜插件，你会如何设计？延展追问：滤镜参数如何保存到 JSON？
   - **答**：图片滤镜插件设计：利用 WebGL 或是 Canvas2D 的像素操作（`getImageData`）。我们将各种滤镜算法（如黑白、冷暖、模糊）封装在插件内，修改滤镜时直接更新图形的 `filters` 参数；导出的 JSON 模板中需要支持该 filter 配置项的序列化存储，以便在二次载入时完美复原滤镜效果。
229. 主问题：插件如何避免破坏核心状态？延展追问：是否需要权限和沙箱？
   - **答**：插件应该通过“只读视图”或有限的“沙箱上下文”进行控制。在项目中，插件不允许直接 new 覆盖编辑器的核心 Canvas 对象，只能通过 DI 容器提供的特定 API 执行操作。在未来可以引入沙箱（如 Sandbox 或 iframe 隔离隔离机制）来防止恶意三方插件窃取用户的敏感模板数据。
230. 主问题：插件系统和普通组件扩展有什么区别？延展追问：什么时候需要插件化？
   - **答**：普通组件扩展是通过修改源码引入新标签，会增加主代码体积；而插件化是在外部声明，运行时动态注入，且与主项目完全解耦。当我们需要为海报设计器提供如“条形码生成”、“AI修图”、“第三方字体市场”等非核心但专业性强的独立功能模块时，最适合采用插件化方案。

### R. 撤销恢复、快捷键与交互

231. 主问题：撤销恢复的核心思想是什么？延展追问：命令模式如何应用？
   - **答**：撤销恢复的核心思想是**命令模式（Command Pattern）**和**快照模式（Memento Pattern）**。每一次改变画布的操作都会被封装成一个 Command 类，它包含 `execute`（执行）、`undo`（撤销）和 `redo`（重做）方法，并通过一个指针在历史记录数组中来回移动实现回滚。
232. 主问题：哪些操作应该进入撤销栈？延展追问：选中状态是否应该可撤销？
   - **答**：应该进入撤销栈的操作：添加/删除图层、移动/缩放元素、修改图层颜色/字体/层级、导入模板等属性修改行为。而诸如“图层选中状态改变”、“侧边栏 Tab 切换”、“视口平移缩放”等不影响海报最终导出效果的纯临时状态，绝对不应该记录进撤销恢复栈中。
233. 主问题：拖拽元素时如何记录历史？延展追问：记录每一帧还是最终状态？
   - **答**：如果记录每一帧，在拖拽元素移动 100px 的过程中会产生上百条细微位移的历史快照，直接导致撤销栈溢出且用户体验极差（需要撤销上百次才能回到原位）。因此，我们只在拖动开始时记录旧状态，在松开鼠标（dragend/mouseup）确定最终位置时，才向历史栈压入这一条最终位置命令。
234. 主问题：导入模板后撤销栈如何处理？延展追问：用户是否应该能撤销导入？
   - **答**：用户成功导入新模板 JSON 后，意味着整个海报的数据模型重置了。为避免出现逻辑混乱，此时撤销恢复栈（UndoRedoService）必须立即执行 `clear()` 清空所有旧的撤销步骤。用户不应该能够撤销“导入模板”这一全局初始化动作，应当把当前模板状态作为全新的历史起点。
235. 主问题：快捷键服务做什么？延展追问：如何绑定 Ctrl+Z、Ctrl+C、Ctrl+V？
   - **答**：快捷键服务通过全局监听 window 的 `keydown` 事件实现。它将按键组合（如 `ctrl+z`、`ctrl+c`）和具体的编辑器命令绑定（如调用 `undoRedoService.undo()` 或 `clipboardService.copy()`），并过滤掉用户在 input、textarea 输入框中的正常打字退格操作，防止快捷键冲突。
236. 主问题：为什么销毁时要 reset keybinding？延展追问：路由切走后快捷键仍生效会怎样？
   - **答**：如果路由切走、编辑器组件销毁时没有 `reset` 注销快捷键监听，window 上的键盘事件监听会依然存活在内存中。当用户在项目的其他非编辑器页面（如设置页、个人中心）打字时，一旦按下了快捷键组合，依然会触发已销毁编辑器的操作方法，导致报错或逻辑冲突。
237. 主问题：复制粘贴如何实现？延展追问：复制的是对象引用还是 JSON 副本？
   - **答**：复制粘贴不能直接复制对象内存引用（否则修改粘贴后的元素会同时修改原元素）。我们必须采用 `JSON 副本` 机制：复制时将当前选中元素的属性导出为 JSON 字符串，粘贴时使用 `uuid` 重新生成全新的业务 id，并在原坐标的基础上向右下角偏移 10px 重新 new 实例化插入画布。
238. 主问题：右键菜单如何和画布对象关联？延展追问：菜单项如何根据对象类型变化？
   - **答**：右键菜单通过定位鼠标事件（`contextmenu`）弹出。菜单项的内容必须通过 `activeObject` 动态判断：如果当前选中的是文本图层，则展示“修改字体”、“编辑富文本”；如果是分组图层，则展示“解散分组”；如果是背景底板，则只展示“设置画布大小”，提升操作效率。
239. 主问题：工具栏如何切换画笔和选择工具？延展追问：工具切换时为什么要清理选中？
   - **答**：当从选择工具（select）切换到画笔或形状绘制工具（draw）时，必须主动调用 `discardActiveObject` 取消当前元素的选中状态。如果不清理，当用户在画布上绘制新圆形时，之前的图片选中框还会亮着，并且可能会因为鼠标点击冲突导致用户无法顺利画出新图形。
240. 主问题：拖拽模式和选择模式如何避免冲突？延展追问：状态机是否适合管理工具模式？
   - **答**：拖拽模式（手掌工具，用于平移视口）和选择模式（鼠标工具，用于缩放元素）是完全互斥的。我们使用状态机（Finite State Machine）或状态模式来管理当前的 `activeTool`。根据状态机的当前状态，画布的事件监听器会动态绑定不同的事件处理函数，避免逻辑打架。

### S. 安全、稳定性与边界情况

241. 主问题：导入用户 JSON 有什么安全风险？延展追问：HTMLText 中的 HTML 是否可能 XSS？
   - **答**：导入用户提供的 JSON 模板时，如果 HTMLText 的 `text` 属性中包含惡意 script 脚本（如 `<img src=x onerror=alert(1)>`），一旦被渲染到浏览器中，就会触发跨站脚本攻击（XSS）。我们必须在解析前使用 DOMPurify 或白名单过滤库对所有的 HTML 属性进行深度消毒净化。
242. 主问题：用户上传图片有什么风险？延展追问：文件类型和大小如何校验？
   - **答**：用户上传的图片素材存在：1. 恶意脚本伪装为图片后缀（如 webshell）；2. 文件过大拖垮服务器。我们需要在前端和后端同时校验：1. 检查文件的 MIME 类型是否为真正的 `image/*`；2. 限制单张图片大小不得超过 5MB，并对过大的图片进行前端预压缩再上传。
243. 主问题：PSD 文件很大时如何防止页面崩溃？延展追问：是否需要大小限制和解析进度？
   - **答**：大 PSD 文件解析非常消耗 CPU，极易导致浏览器假死甚至崩溃。我们需要：1. 在前端对上传的 PSD 文件大小做限制（如最大 150MB）；2. 使用 `FileReader` 的流式读取或在 Web Worker 中后台解析；3. 使用进度条展示当前的解析进度百分比，避免用户认为网页死机而高频操作。
244. 主问题：第三方库异常如何处理？延展追问：try/catch 应该放在哪些边界？
   - **答**：在与第三方库交互（如调用 ag-psd 解析二进制、调用 html2canvas 截图、以及使用 fontfaceobserver 监听字体）时，必须用 `try...catch` 进行边界包裹。这能够防止第三方库因内部错误或浏览器环境不兼容直接抛出未捕获的 Fatal Error，保障主应用能安全处理报错而不崩溃。
245. 主问题：localStorage 缓存字体有什么风险？延展追问：缓存版本如何失效？
   - **答**：缓存字体到 localStorage 时，如果字体文件过多（如几十个，每个几MB），会瞬间撑爆 localStorage 5MB 的存储上限。此外，如果后端修改了字体的样式文件而前端缓存未更新，会导致字体错乱。必须通过引入 `Cache-Version` 版本号和设置存储容量白名单进行控制和失效更新。
246. 主问题：画布对象缺少必要字段怎么办？延展追问：导入 JSON 前如何做 schema 校验？
   - **答**：如果 JSON 模板数据因损坏缺失了如 `width` 或 `height` 核心字段，会导致 Leafer 实例化时直接报 NaN 错误并黑屏。我们在解析前必须通过一套 JSON Schema 格式校验工具进行初始检测，遇到必填项缺失时自动使用默认预设值（如 800x1200）进行兜底补全。
247. 主问题：接口返回空数据怎么办？延展追问：UI 层如何展示占位符？
   - **答**：当网络请求返回的素材列表或模板列表为空数据（empty data）时，为了不给用户留下“系统坏了”的困惑，UI 层（Vue 组件）必须通过条件渲染（`v-if="list.length === 0"`）来渲染一个统一的空状态占位符（Empty Placeholder Component）和提示文案。
248. 主问题：浏览器兼容如何处理？延展追问：Canvas、ResizeObserver、FontFace 是否都兼容？
   - **答**：我们在初始化时，会编写一个 feature check 检测脚本：检测当前浏览器是否支持原生 `CanvasRenderingContext2D`、`ResizeObserver` 以及 `FontFace` API。如果遇到不支持的老旧浏览器，会引导用户下载升级现代浏览器（如最新版 Chrome），并做好部分特性的 polyfill 降级处理。
249. 主问题：内存泄漏可能来自哪里？延展追问：事件监听、画布实例、图片资源如何释放？
   - **答**：内存泄漏通常来源于：1. 卸载页面时没有移除 `window.addEventListener` 的 resize/keydown 监听；2. Leafer Canvas 实例没有执行 `destroy()` 被永久缓存在闭包中；3. 图片通过 `URL.createObjectURL` 临时生成的内存 URL 没有在图片加载完后执行 `revokeObjectURL` 释放内存。
250. 主问题：如何做错误日志上报？延展追问：编辑器操作上下文如何记录？
   - **答**：我们通过在 `errorCaptured` 和全局 `window.onerror` 中捕获异常，并实时收集报错堆栈。为了方便还原现场，我们会将当前编辑器的最后 10 步历史操作日志、当前模板的 ID 以及用户的浏览器 UA 环境信息，一并组装成 JSON 报文异步上报给 Sentry 或日志服务器。

### T. 测试与质量保障

251. 主问题：这个项目如何做单元测试？延展追问：工具函数和 parser 哪些最适合测？
   - **答**：最适合做单元测试（Unit Test）的是那些不依赖 DOM 环境的纯工具函数，例如 [getFileExt](file:///d:/项目相关/AAA/gzm-design/src/utils/designUtil.ts#L3)（获取文件后缀）、[checkFileExt](file:///d:/项目相关/AAA/gzm-design/src/utils/designUtil.ts#L43)（校验类型）、以及将 PSD 图层颜色进行转义的 parser 工具函数。我们可以使用 Vitest 框架编写测试断言。
252. 主问题：画布编辑器如何做自动化测试？延展追问：如何验证拖拽、缩放、选中？
   - **答**：可以使用 Cypress 或 Playwright 等 E2E 自动化测试工具。在测试用例中：通过选择器选中画布的特定 DOM，模拟鼠标的 mousedown、mousemove 和 mouseup 事件序列来实现拖动元素的测试，并通过比对被操作后元素的位置 `x` 和属性值来判断测试是否通过。
253. 主问题：PSD 解析如何测试？延展追问：快照测试是否适合 JSON 输出？
   - **答**：PSD 解析最适合使用**快照测试（Snapshot Testing）**。我们将一些结构标准的 PSD 测试文件存入测试库，运行解析器后，将输出的 JSON 结构与之前保存的正确基准快照 JSON 进行比对。如果发现解析出的 children 字段或图层类型发生意外改变，测试就会立刻报警。
254. 主问题：多页面切换如何测试？延展追问：如何验证切换前保存、切换后恢复？
   - **答**：通过自动化测试脚本，模拟用户依次点击页面列表中的 `Page 1` 和 `Page 2`。测试用例在点击前，先断言验证 WorkspacesService 是否发出了 `workspaceChangeBefore` 且 Map 中成功保存了当前页面的 JSON，在切页后，断言验证当前 activeId 是否更新且 Canvas 上的 children 成功替换为新数据。
255. 主问题：字体加载如何测试？延展追问：如何 mock FontFaceObserver？
   - **答**：我们通过在单元测试或集成测试中，手动重写（mock）全局的 `window.FontFace` 和 `FontFaceObserver` 构造函数。让它们的 `load()` 方法不发真实的 CDN 字体网络请求，而是通过 `setTimeout` 直接返回一个成功加载的 Promise，从而加速测试流程并隔离外部网络依赖。
256. 主问题：导出图片如何测试？延展追问：像素级对比有什么难点？
   - **答**：导出图片的测试难点在于：不同的操作系统、浏览器渲染引擎在绘制 Canvas 图形和文字时，存在肉眼不可见但像素值不一致的微小渲染偏差（Subpixel rendering）。因此不能使用二进制哈希值直接对比，而必须使用 `pixelmatch` 库并设置一定的相似度容差阀值（如 99.5% 相似度）。
257. 主问题：组件属性面板如何测试？延展追问：如何模拟 activeObject？
   - **答**：可以通过在 Vitest 环境下 mock 创建一个包含部分属性的 activeObject 的 shallowRef，将其作为 provide 注入到被测试的 `rightPanel` 属性组件中。模拟修改组件中的 Slider 滑块值，断言检测 activeObject 对象的对应属性（如 width/height）是否同步被修改。
258. 主问题：事件总线如何测试？延展追问：如何验证事件触发顺序？
   - **答**：在测试脚本中，我们可以为 `EventbusService` 的指定事件（如 `activeObjectChange`）注册一个 Spy 监听函数（如 Vitest 的 `vi.fn()`）。当触发了画布的选中动作后，断言验证该 Spy 函数是否被成功调用，且传入的第一个参数是否为当前选中的元素实例。
259. 主问题：依赖注入服务如何测试？延展追问：如何替换一个 fake service？
   - **答**：通过在初始化测试容器（Test Container）时，向 `ServiceCollection` 中注入我们提前写好的 Mock 实现。例如将 `HttpService` 替换为 `MockHttpService`。由于各个依赖它的服务在构造时都是通过装饰器声明并由容器解析的，所以会被自动替换为 mock 服务，无需改动被测服务代码。
260. 主问题：如何做回归测试？延展追问：编辑器项目哪些功能最容易回归出问题？
   - **答**：编辑器项目中，**撤销恢复栈（Undo/Redo）**和**图层层级调整（Hierarchy）**最容易在业务迭代中回归出 Bug。例如新增了某个复杂元素（如表格），可能在拖动时忘记向历史栈中压入位置信息，导致撤销它时报错。针对这两个高危模块必须设计全覆盖的自动化冒烟测试用例。

### 2. 回答示例：为什么使用依赖注入

可以这样回答：

这个项目的编辑器不是单个组件能解决的，它有画布服务、工作区服务、事件总线、快捷键、图层、撤销恢复等多个模块。如果每个模块都自己 import 并 new 其他模块，会导致依赖关系混乱，也不利于后续替换和测试。所以项目使用依赖注入，把服务注册到容器里，需要服务的类通过构造函数声明依赖，由容器统一创建。这样服务边界更清楚，也能创建编辑器级的子容器，方便未来支持多个编辑器实例。

可能追问：依赖注入有没有缺点？

可以回答：有。它会增加理解成本，新手不容易直接看出实例在哪里创建；如果服务依赖关系复杂，也可能出现循环依赖。所以不是所有项目都需要 DI。普通页面可以用普通 import 和组合式函数，但复杂编辑器、多服务协作、需要插件化扩展时，DI 的收益会更明显。

### 3. 回答示例：为什么不用 Pinia 管理全部画布状态

可以这样回答：

Pinia 适合管理业务状态，比如当前工具、字体列表、用户信息等。但 Leafer 的画布对象是复杂实例，包含大量方法、事件、内部状态和可能的循环引用。如果全部放进 Pinia，会被响应式系统代理，带来性能和行为风险。因此项目只把轻量业务状态放进 Pinia，把画布实例、contentFrame、activeObject 等核心画布状态放在 `MLeaferCanvas` 服务里，并用 shallowRef 暴露必要响应式引用。

### 4. 回答示例：PSD 导入难点

可以这样回答：

PSD 导入的难点不是读文件本身，而是格式转换。`ag-psd` 可以把 PSD 解析成图层数据，但 Photoshop 的图层属性和 Leafer 的画布对象不是一一对应的。比如文本要区分普通文本和富文本，字体大小还要考虑 transform 缩放，颜色要做格式转换，描边、段落对齐、下划线、删除线、分组、蒙版都要映射到编辑器支持的属性。并且字体加载不完整时，导入后的视觉效果会和 PSD 有偏差，所以导入后还要提取字体并触发重新渲染。

### 5. 回答示例：多页面如何实现

可以这样回答：

多页面通过 WorkspacesService 和 MLeaferCanvas 协作实现。WorkspacesService 管理页面 id 和名称，MLeaferCanvas 用 Map 保存每个页面对应的 JSON。切换页面时，工作区服务先发 `workspaceChangeBefore`，画布服务监听后把当前 contentFrame 转成 JSON 保存；然后工作区服务更新 currentId 并发 `workspaceChangeAfter`，画布服务再清空当前画布并导入目标页面 JSON。这样工作区服务不需要知道画布细节，画布服务也不需要直接管理 UI 点击逻辑。
